# 第八册　开发与工具链

> 编程语言、终端、编辑器、版本控制与构建

前七册把一台 Arch 机器装好、调稳、联网、配上桌面、装满软件，读者到这里仍只是“使用者”。本册补上另一半：同一台机器如何变成工作台。读完本册，你应该能按任务挑出合适的语言运行时与构建方式，并从官方仓库而不是随手抓来的脚本里装好；能把 shell、终端模拟器与多路复用器调成一套可重复、断线可续的工作环境；能选定一款编辑器并真正用它写代码，而不是每周换一次；能用 Git 管住改动，把本地试过的源码做成 pacman 能装的包；也能在没有图形界面的机器上完成以上全部。合起来只有一句话：把 Arch 当开发平台用，而不是当成品用。

## 本册在九册中的位置

本册夹在“会用系统”与“守好系统”之间。向前，它依赖第二册：软件包管理给出的安装、编译与打包规矩，是本册构建话题的延长线；也依赖第三册，工具链出错时，内核、权限、服务与日志的知识决定你能否自己查下去。第四册的 SSH 是远程仓库与远程开发的地基，第七册从用户视角看过那批软件，本册换到产出者的位置重看一遍。向后交给第九册：提交签名、密钥管理、构建环境隔离与沙箱，都是本册特意留下的接口。

## 推荐阅读顺序

前两章（编程语言与开发）是骨架，篇幅也最重，建议按顺序读完，它们决定后面所有工具的使用场景。终端相关的几章——命令行解释器、终端模拟器、命令行本身与终端多路复用器——请当作一组连读，它们互相咬合，拆开读会反复回头。文本编辑器与 Linux 控制台属于个人口味，挑一个读到能干活，另一个留作备查。版本控制系统与 Git 网络界面不论是否写代码都值得花时间，这是少数能立刻改善日常工作的部分。册尾的专项章节（Lisp 方言、TeX、控件工具集、电子设计自动化等）按需查阅，跳读不影响主线；框架一章留给正在选型的人。

## 前置知识与常见误区

前置是：熟练的命令行操作（管道、重定向、权限、文本处理），第二册的软件包与打包部分——至少能看懂 PKGBUILD，分清官方仓库、AUR 与本地编译的边界；第三册关于用户、权限与服务的基础知识；再加一条能连通的 SSH 通道。这些不牢就先回去补，本册不会重复解释。

几个误区值得先说。其一，以为“搭开发环境”就是装一个 IDE：语言运行时、shell、编辑器、版本控制与构建系统其实是五件独立的事，可以自由组合，本册按部件而非按产品组织。其二，把语言自带的包管理器当作唯一入口，直接往系统目录里堆库文件，既绕过 pacman 的记账，也会在滚动更新后留下难查的冲突；正解是让系统包与语言级环境各守一段，项目级隔离不是可选项。其三，把终端各章当成程序员专区——它们同样服务于运维、写作与日常操作，跳过是纯损失。
