# 第 2 章　终端与命令行

## 为什么 Arch 离不开终端

大部分发行版在第一次开机时就把桌面摆好了：图标、菜单、设置面板，每件事都有对应的按钮。Arch 的做法不同，它给你的是一套工具，而不是一件成品。好处是你能完全决定系统长什么样，代价是很多步骤没有现成的按钮可点。

安装 Arch 本身，官方给出的流程就是一行行命令；系统装好之后，更新靠的也是一条命令，而不是某个“检查更新”的图标。这不是说 Arch 用不了图形界面——它的桌面环境和其他发行版一样齐全。只是当系统出问题、需要看清它到底做了什么的时候，图形界面会把细节藏起来，命令行不会。

所以这一章的目标不是让你背下命令，而是让你在面对一个空白的终端窗口时，知道自己在敲什么。

## 终端里住着一个 shell

先分清两样东西，它们经常被混为一谈。

终端（terminal）是你看到的那个窗口。它本身几乎不做决定，只负责显示文字、接收按键。窗口里真正干活的程序叫 shell，中文常译作“壳”——包在操作系统内核外面的一层壳。

shell 的职责是一个循环：打印提示符，等你敲一行字；把这一行读进来，解析成“要运行哪个程序、带哪些材料”；把程序跑起来；等它结束，把结果交回屏幕；然后接着等下一行。这个循环一直重复，直到你关掉窗口。

Arch 默认的 shell 是 bash。你敲下的每个字都先经过它，由它决定把工作交给谁。也正因为有这一层，命令行里能做的事情，比任何一个图形程序都要多。

## 一条命令由什么组成

看这一行：

```
$ ls -l /home
```

用空格切开，它是三个词。

第一个词 `ls` 是命令名（command），实际上是一个可执行文件的名字。shell 拿到它之后，会去几个约定的目录里找这个文件，找到就运行。

以减号开头的是选项（option），也叫标志（flag）。`-l` 表示用长格式列出，多显示权限、大小、时间这些信息。要留意：选项是每个命令自己定的规矩，不是 shell 的规则，同一个 `-l` 在这里是这个意思，换个命令可能就是别的意思。单字母选项写一根减号，完整单词的写法用两根，比如 `--all`。

剩下不带减号的部分叫参数（argument），说明这条命令作用在什么对象上。上面的 `/home` 就是一个参数。

命令名大多是从英文里截短的：`ls` 来自 list，`cd` 来自 change directory，`cp` 来自 copy，`mv` 来自 move，`rm` 来自 remove，`pwd` 是 print working directory 的缩写，`grep` 则出自编辑器里的 global regular expression print。知道出处，就不必死记。

空格在这件事上很重要。shell 靠空格切分词语，`ls -l` 是两个词，`ls-l` 会被当成一个不存在的命令名。多打一个空格通常无所谓，少打一个通常报错。

## 路径：东西放在哪儿

参数里最常见的是路径（path），也就是某个文件或目录的位置。

以斜杠 `/` 开头的叫绝对路径（absolute path），从文件系统的最顶层——根目录（root）——一路写下来。`/home` 的意思就是“根目录下的 home”。不论你现在站在哪里，绝对路径指向的都是同一个地方。

不以斜杠开头的叫相对路径（relative path），相对于你当前所在的位置。有两个符号要记住：`.` 表示当前目录，`..` 表示上一级目录。所以 `cd ..` 的意思是退回上一层。

还有个偷懒的写法：`~` 代表你的家目录（home directory），也就是你登录之后默认待的地方。它展开后是一串很长的绝对路径，但你不用记。

顺带一提，Linux 的路径分隔符是正斜杠 `/`，不是 Windows 习惯的反斜杠 `\`。这一条最容易让从 Windows 转过来的人出错。

## 管道与重定向

每个程序默认有两个出口和一个入口：出口是屏幕，分别叫标准输出（standard output）和标准错误（standard error）；入口是键盘，叫标准输入（standard input）。shell 可以改接这几条通道，这就是重定向（redirection）。

```
$ echo hello > note.txt
```

`>` 把本来该显示在屏幕上的内容送进文件。文件不存在会被创建，已经存在会被整个覆盖——覆盖是不打招呼的，所以对着一个正在用的文件敲 `>`，很容易把里面的内容清空。想接在后面而不是覆盖，用 `>>`。反方向的 `<` 表示从文件读入，而不是等你敲键盘。

管道（pipe）的符号是竖线 `|`，它把前一条命令的输出直接变成后一条命令的输入，中间不必写成文件。

```
$ ls /etc | wc -l
```

前半句列出目录内容，后半句数行数，合起来就是“数一数这个目录下有多少个条目”。把小的程序首尾相接去解决一个大问题，是命令行最核心的思路：不指望有一个什么都干的程序，而是让很多只干一件事的程序串起来。

## 十个最常用的命令

先看它们长什么样，再逐条解释。

```
$ ls                      # 列出当前目录的内容
$ cd /etc                 # 切换到 /etc 目录
$ pwd                     # 打印当前所在目录
$ cat note.txt            # 把文件内容整体打印出来
$ less /etc/fstab         # 分页浏览文件
$ mkdir demo              # 新建一个目录
$ rm note.txt             # 删除文件
$ cp a.txt b.txt          # 复制
$ mv a.txt b.txt          # 移动或改名
$ grep root /etc/passwd   # 在一个文件里找出包含 root 的行
```

`ls`、`cd`、`pwd` 是“有什么、去哪儿、我在哪”的三件套。`cd` 不带参数会回到你的家目录，`cd -` 会回到上一次待过的目录。

`cat` 适合看一屏之内就能读完的短文件；`less` 适合看长文件，空格往下翻，方向键上下看，`/` 后面跟关键词可以在页内搜索，按 `q` 退出。

`mkdir -p` 能一次性建出多层目录，中间几层不存在也不会报错。

`rm` 要格外小心：命令行里没有回收站，删掉就是删掉。删目录得加 `-r`（递归处理），复制目录同样要 `cp -r`。你在网上的教程里会频繁见到 `rm -rf`，它的意思是递归并且不再逐项确认——这条命令不区分对象，一次手滑就可能造成无法挽回的损失。不确定的时候，先用 `ls` 看清楚目录里是什么。

`mv` 同时承担“移动”和“改名”两件事，因为在文件系统里这本来就是同一种操作：换个名字，或者换个位置。

`grep` 在文件里按文本匹配，找某个配置项、翻某条日志都用它。

除了这十个，还有一个命令你迟早会天天用：`pacman -Syu` 用来同步软件源并升级整个系统。它属于包管理，后面有专门一章。

## 敲的时候不必全靠记忆

试一次就会发现，命令并不需要一次打对。

打到一半卡住，按一次 Tab 键：如果剩下的部分只有一种可能，shell 会替你补完；如果有多个候选，再按一次会把它们列出来。路径越长、文件名越怪，这个键越有用——按一下 Tab 往往比盯着屏幕回想可靠得多。

另一种省事的办法是翻历史。上下方向键可以在敲过的命令之间来回切换，找到想再跑一次的那条，按回车。刚上手时，很多操作就是在上一条的基础上改一两个词。

这两样都是 shell 提供的，不是某个命令的功能。bash 默认就带着它们，所以从第一次打开终端起，你就能用。

## 不认识的东西，去哪儿问

命令行的命令成千上万，没人记得住。好消息是不用记住——几乎每个程序都自带说明书。

短的那份，是在程序后面加 `--help`：

```
$ ls --help
```

很多程序都实现了它，输出一段简短的用法摘要，够你确认某个选项怎么拼。但它是程序自己实现的约定，不是 shell 的规矩，所以偶尔也会遇到不认这个参数的程序。

完整的那份是手册页（manual page），用 `man` 打开：

```
$ man ls
```

手册页会把每个选项的意思逐条列出，后面通常还有示例和注意事项。读的时候，空格往下翻，`q` 退出，输入 `/` 再跟关键词可以在页内搜索。

手册页分成若干节：第 1 节是用户命令，第 5 节是文件格式，第 8 节是系统管理命令。同一个名字出现在不同节时，可以在名字前面写节号指定，比如 `man 5 passwd` 查的是密码文件格式，而不是改密码的那个命令。

这两条路的区别很简单：`--help` 快，够用就停；`man` 全，要弄清细节的时候再看。

到此为止，你已经知道一条命令由哪几部分组成、结果会流向哪里，也知道了该去哪儿查你不会的东西。真正让人卡住的从来不是记不住命令，而是不知道该去哪里找答案——这个问题的答案，现在你有了。
