# 第 3 章　文件系统与权限

## 一切皆文件

Linux 里有一句话几乎能解释所有奇怪现象：一切皆文件（everything is a file）。它的意思不是"所有东西都是文本"，而是说系统给各种资源套上了同一层接口——打开、读取、写入、关闭。

普通文档是文件；目录是文件；硬盘是文件；键盘是文件；正在运行的进程的状态也可以是文件。比如 `/dev/sda` 代表第一块硬盘，往它上面写字节就是往硬盘上写字节；`/proc/cpuinfo` 里读到的是一份"文件"，其实是内核在你读取时现场生成的 CPU 信息。它们不占多少磁盘空间，却都能用同样的 `cat`、同样的重定向 `>` 去操作。

这层统一的代价是抽象：你必须先知道"这个文件代表什么"，才能理解对它操作会发生什么。好处是，几乎所有的工具都只需要会操作文件，就能操作整个系统。

## 目录树与 FHS

文件系统（file system）是把存储空间组织成文件与目录的规则。Linux 把所有这些目录串在一棵树上，树根是 `/`，也就是根目录。没有 C 盘 D 盘，只有 `/` 和它下面的分支。一条路径从 `/` 写起叫绝对路径（absolute path），从当前目录写起叫相对路径（relative path）；`.` 表示当前目录，`..` 表示上一级。

树的形状不是内核随意决定的，而是遵循一份约定，叫文件系统层次结构标准（Filesystem Hierarchy Standard，FHS）。先记住主干即可：

```text
/            根，一切从这里开始
├── etc      系统和软件的配置文件
├── home     普通用户的家目录，形如 /home/用户名
├── root     root 用户的家目录（它不在 /home 下）
├── usr      系统和软件安装的内容
├── var      会变的数据：日志、缓存、数据库
├── tmp      临时文件，重启后不保证还在
├── dev      设备文件
├── proc     内核暴露的进程与系统信息
├── sys      内核暴露的设备与驱动信息
├── boot     内核和引导相关文件
├── mnt      手动挂载用的位置
└── opt      额外安装的软件
```

看到 Arch Wiki 上写"编辑 `/etc/xxx.conf`"或"日志在 `/var/log`"，指的就是这棵树里的固定位置。理解 FHS 的价值在于：你能大概猜到一个陌生文件属于哪一类，也能判断一条教程里的路径是否合理。

## 读懂 ls -l 的每一列

`ls` 只给名字，加 `-l` 才给细节。典型的输出长这样（示例，名字是虚构的）：

```text
$ ls -l
-rw-r--r-- 1 alice users 4200 Mar  8 10:12 notes.txt
drwxr-xr-x 2 alice users 4096 Mar  8 09:30 docs
lrwxrwxrwx 1 root  root     7 Mar  1 08:00 lib -> usr/lib
```

从左往右，一共七列。

第一列的前十个字符是重点，先拆成"类型 + 九位权限"。第一位是文件类型：`-` 普通文件，`d` 目录，`l` 软链接，`c` 字符设备，`b` 块设备，`p` 命名管道，`s` 套接字。随后的九个字符切成三组，分别是属主（owner，也叫 user）、属组（group）、其他人（others）的权限，每组三位，依次是 `r`、`w`、`x`，没有该权限就显示 `-`。

- `r`（read，读）：对文件是能读出内容；对目录是能列出里面有哪些名字。
- `w`（write，写）：对文件是能改内容；对目录是能在里面创建、删除、重命名文件。
- `x`（execute，执行）：对文件是能当作程序运行；对目录是能进入并穿过它访问里面的东西。

目录的 `r` 和 `x` 必须分开理解，这是新手最容易卡住的地方。只有 `r` 没有 `x`，你能看到目录里有哪些文件名，却打不开其中任何一个；只有 `x` 没有 `r`，你进得去、能访问已知名字的文件，但列不出目录内容。

第二列是硬链接（hard link）计数，下文细说。第三、四列是属主和属组。第五列是大小，普通文件以字节计；设备文件这一列显示的是主设备号和次设备号，不代表存储容量。第六列是最后修改时间。第七列是名字；如果是软链接，还会跟一个 `->` 和它指向的目标。

`ls -l` 后面不加参数时列的是目录里的内容。想看目录本身的信息要用 `ls -ld 目录名`，否则你看到的是目录里面，而不是目录这个"文件"本身。

## 权限怎么算，怎么改

`r`、`w`、`x` 各对应一个数值：`r` 是 4，`w` 是 2，`x` 是 1。三位一组求和，就得到一位八进制数字。于是三组正好三位数：

- `rwxr-xr-x` → 755
- `rw-r--r--` → 644
- `rwx------` → 700

改写权限用 `chmod`（change mode）。数字写法直接给三位数：

```text
$ chmod 644 notes.txt
$ chmod 755 script.sh
```

符号写法更直观，`u` 代表属主、`g` 代表属组、`o` 代表其他人、`a` 代表全部，`+` 加权限、`-` 减权限、`=` 直接设成：

```text
$ chmod u+x script.sh
$ chmod go-w notes.txt
```

新建文件的初始权限不是凭空来的。系统先给出一个"上限"，文件通常是 666，目录通常是 777，再按掩码（umask）把某些位清掉。常见的 umask 是 022，于是普通文件落在 644，目录落在 755。注意这是按位清除，不是算术减法。

属主和属组用 `chown`（change owner）改，属组也可以用 `chgrp`：

```text
# chown alice notes.txt
# chown alice:users notes.txt
```

这两条前面用 `#`，因为改属主属于特权操作，普通用户只能把自己的文件转给别人名下这一种情况几乎不成立，实践中都要 root。`-R` 可以递归处理整个目录，但请务必确认路径再按回车——递归改错属主会让系统文件出问题。

还有两个特殊的权限位值得认识。一个是粘滞位（sticky bit），在权限串里显示为 `t`，比如 `/tmp` 是 `drwxrwxrwt`：谁都往里写，但只能删除自己的文件，删不了别人的。另一个是设置用户 ID（setuid），显示为属主执行位上的 `s`。像 `/usr/bin/passwd` 是 `-rwsr-xr-x`，普通用户执行它时，进程会临时以文件属主（这里是 root）的身份运行，这正是"普通用户也能改自己的密码"的原因。

顺带说一句 root 和权限的关系：root 基本可以绕过读和写的检查，但想执行一个文件，仍然需要它至少有一个 `x` 位。所以"root 什么都行"也不完全对。

## 硬链接与软链接

要理解链接，先要理解索引节点（inode）。文件系统里真正记录"数据在磁盘的哪里、多大、谁拥有、什么时候改过"的结构是 inode，文件名只是贴在这个 inode 上的一个标签。目录的本质就是一张"名字 → inode 编号"的表。

硬链接（hard link）就是给同一个 inode 再贴一个标签。用 `ln 原文件 新名字` 创建。两个名字完全平等，没有谁是"原件"，删掉其中一个，另一个照样能打开；只有当链接计数归零，数据才真正被回收。`ls -l` 的第二列就是这个计数，新建的普通文件是 1，每多一个硬链接就加 1。目录的这个数字含义稍有不同：每个目录自带一个 `.` 指向自己，再加上它在上层目录里的那个名字，起点就是 2，之后每多一个子目录再加 1。

硬链接有两条硬限制：不能跨文件系统，因为 inode 编号只在单个文件系统内唯一；一般也不允许给目录建硬链接，否则容易造出循环的目录树。

软链接（symbolic link，也叫符号链接）是另一种东西：它本身是一个独立的小文件，内容是"我要指向的那个路径"。用 `ln -s 目标 链接名` 创建。它能跨文件系统，能指向目录，也能指向一个根本不存在的位置——这种叫悬空链接（dangling symlink），访问时会报"No such file or directory"。

两者的差别可以用 `ls -i` 看 inode 验证：硬链接的两个名字 inode 相同，软链接的 inode 不同。软链接多一次跳转，代价是目标一旦改名或挪走它就失效；硬链接没有这个风险，但要占用额外的目录条目且受文件系统限制。

Arch 系统里 `/bin`、`/sbin`、`/lib` 都是指向 `/usr` 下对应目录的软链接。这不是凑巧，而是"usr 合并"（usr merge）的结果：历史上这些目录是分开的，现在统一收进 `/usr`，旧路径保留为软链接，老教程里的 `/bin/ls` 依然能用。这也是为什么读老资料时看到 `/bin` 不要觉得它已经过时。

删除软链接要删链接本身，用 `rm 链接名`，这样不会碰到目标。注意不要在名字后面多打一个斜杠：`rm link/` 会因为要求它必须是个目录而直接报错，什么也删不掉。

## 挂载：目录树是怎么长出来的

硬盘、分区、U 盘这些存储设备，在格式化之后只是"一块有文件系统的空间"。它不会自动出现在目录树里，需要被"接"上去才看得见。这个动作叫挂载（mount），接上去的那个目录位置叫挂载点（mount point）。挂载完成后，你访问那个目录，看到的就是那块存储的根目录。

```text
# mount /dev/sdb1 /mnt
# umount /mnt
```

看当前有哪些块设备、谁挂在哪里，常用 `lsblk`；看各挂载点还剩多少空间，用 `df -h`。

理解挂载最关键的一点是：挂载会"盖住"挂载点目录原本的内容。原来的文件并没有被删除，只是被暂时遮住，卸载之后又会露出来。所以把重要文件写进一个准备当挂载点的目录，是很常见的踩坑方式——挂载之后它们"消失"，卸载之后它们又回来了。

开机时要自动挂载的条目写在 `/etc/fstab` 里，大致是"设备 挂载点 文件系统类型 选项"这样的几列。这个文件写错可能让系统起不来，动手之前先备份，改完用 `mount -a` 之类的方式验证一遍再重启。

`/proc`、`/sys`、`/dev` 这些目录也是在系统启动过程中由内核挂上来的，属于伪文件系统（pseudo filesystem）：里面没有真正的磁盘数据，读到的是内核此时此刻的状态。这也正好回到开头那句话——它们也是文件，只是背后没有硬盘。

权限和挂载这两件事，几乎每一页 Arch Wiki 都会碰到：改一个配置文件的权限、往 `/etc` 里添一个文件、把新分区挂到 `/mnt` 再搬东西进去。把这一章的读法练熟，后面看文档时就不必再猜那些符号是什么意思了。
