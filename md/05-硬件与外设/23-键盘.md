# 第 23 章　键盘

> 在 Arch 上，键盘的麻烦很少出在能不能打字，而集中在两处：开机后数字锁定键不亮，以及快捷键不合手。前者看似只是一个开关，实际要分控制台、X.org、Wayland 三套独立的配置；后者则要先分清哪些是默认值、哪些得自己改。
> 
> 阅读顺序上，《快捷键》必读，默认快捷键、自定义快捷键与参见都集中在这一节；《启动时打开数字锁定键》可以先跳过，等确实想开机即开小键盘时再读，那时三处都要顾到。最容易踩的坑，是以为改一处就全局生效——控制台的办法管不到图形会话，X.org 与 Wayland 的写法也不能互相照搬。

## 23.1　启动时打开数字锁定键

*难度：进阶 ｜ 篇幅：8.5 KB ｜ 所属：键盘*

将要讲到：控制台、X.org、Wayland

## 控制台

### 早期启动 (mkinitcpio)

您可以在内核启动后立即在 initramfs 中启用 numlock。这是确保即使在输入[全盘加密](../../08_安全与加密/静态数据加密/Dm-crypt_加密整个系统.md)密码期间 numlock 也开启的唯一方法。安装 [mkinitcpio-numlock](https://aur.archlinux.org/packages/mkinitcpio-numlock/)AUR ，并在 `/etc/mkinitcpio.conf` HOOKS 数组中的 `encrypt` 之前添加 `numlock` [mkinitcpio](../../01_安装与包管理/Initramfs/Mkinitcpio.md) 钩子：

```
/etc/mkinitcpio.conf
```

```
...
HOOKS=(base udev autodetect microcode modconf kms keyboard keymap consolefont numlock block encrypt lvm2 filesystems fsck)
...
```

然后重新[生成镜像](../../01_安装与包管理/Initramfs/Mkinitcpio.md#创建和启用镜像)以应用更改。

> **注意：**`numlock` 钩子在基于 systemd 的 [initramfs](../../01_安装与包管理/启动过程/Arch%20的启动流程.md) 上不起作用。这种情况下，可以安装 [mkinitcpio-sd-numlock](https://aur.archlinux.org/packages/mkinitcpio-sd-numlock/)AUR 并在 initramfs 配置中使用 `sd-numlock`。

使用此方法的优势在于，numlock 设置将在后续启动过程中被复制，并且新的虚拟控制台将默认开启 numlock。

### 使用 systemd 服务

> [![](https://wiki.archlinuxcn.org/wzh/images/d/d6/Tango-inaccurate.png)](https://wiki.archlinuxcn.org/wzh/File:Tango-inaccurate.png)**本文或本章节的事实准确性存在争议。**
>
> **原因：** numlockx 只能用于 X11，不能用于 Wayland。（在 [en:Talk:Activating numlock on bootup](https://wiki.archlinux.org/title/Talk:Activating_numlock_on_bootup) 中讨论）

> **提示：**安装 [systemd-numlockontty](https://aur.archlinux.org/packages/systemd-numlockontty/)AUR 并启用 `numLockOnTty` 服务可以替代这些步骤。

首先安装 [numlockx](https://archlinux.org/packages/?name=numlockx)包。

然后创建在特定 TTY 上设置 numlock 的脚本：

```
/usr/local/bin/numlock
```

```
#!/bin/bash

for tty in /dev/tty{1..6}
do
    /usr/bin/setleds -D +num < "$tty";
done
```

创建好文件后，添加可执行权限，这样才能运行脚本。

然后创建并启用 systemd 服务:

```
/etc/systemd/system/numlock.service
```

```
[Unit]
Description=numlock

[Service]
ExecStart=/usr/local/bin/numlock
StandardInput=tty
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
```

### 扩展 getty@.service

这个方法比使用单独服务简单，不需要在脚本中写入 TTY 编号。在原始 gettty 单元文件上添加一段扩展：

```
/etc/systemd/system/getty@.service.d/activate-numlock.conf
```

```
[Service]
ExecStartPre=/bin/sh -c 'setleds -D +num < /dev/%I'
```

要禁用登录屏幕上的数字键启用提示，编辑 `getty@tty1.service`，添加 `--nohints` 到 agetty 选项:

```
[Service]
ExecStart=
ExecStart=-/sbin/agetty --noreset --nohints --noclear - ${TERM}
```

### Bash 替代方案

将 `setleds -D +num` 加入到 `~/.bash_profile`。需要注意的是，不同于其他方法，这种方式将会在你登录后才生效。

## X.org

有许多可选方案：

### startx

安装 [numlockx](https://archlinux.org/packages/?name=numlockx)包 包，并将其添加到 ~`~/.xinitrc`~ [xinitrc](../../05_桌面与图形/Xorg%20命令/Xinit.md#xinitrc) 文件所有 ~`exec`~ 语句前：

```
~/.xinitrc
```

```
numlockx &
exec window manager
```

### MATE

MATE 默认会保存上次启动时的数字键盘状态，要确保每次启动都启用：

```
$ dconf write org.mate.peripherals-keyboard remember-numlock-state false
$ dconf write org.mate.peripherals-keyboard numlock-state 'on'
```

### KDE Plasma

前往**系统设置** > **输入和输出** > **键盘**，在**键盘**标签页的 **NumLock 在开机时的状态**部分，选择所需的 NumLock 行为。

要使其生效，请确保**系统设置** > **系统** > **会话** > **后台服务** > **键盘守护进程**已启用。

> **注意：**如果在 KDE Plasma 中无法通过**系统设置**访问**后台服务**部分，运行 shell 命令 `kcmshell6 kcm_kded`（必要时替换为您的 kcmshell 版本）应该会显示此菜单。

### GNOME

运行下面命令:

```
$ gsettings set org.gnome.desktop.peripherals.keyboard numlock-state true
```

要记住上次的 numlock 状态:

```
$ gsettings set org.gnome.desktop.peripherals.keyboard remember-numlock-state true
```

或者也可以将 `numlockx on`（来自 [numlockx](https://archlinux.org/packages/?name=numlockx)包）添加到启动脚本或 `~/.profile` 中。

### GDM

创建以下 dconf 配置文件：

```
/etc/dconf/db/gdm.d/90-numlock
```

```
[org/gnome/desktop/peripherals/keyboard]
remember-numlock-state=true
numlock-state=true
```

根据 [gsettings 定义](https://github.com/GNOME/gsettings-desktop-schemas/blob/8c672b3a0b659ddafb361411f820589627653642/schemas/org.gnome.desktop.peripherals.gschema.xml.in#L107)，`remember-numlock-state` 决定是否记住并恢复上次的 numlock 状态，而 `numlock-state` 提供的是上次的 numlock 状态。[mutter 源代码](https://github.com/GNOME/mutter/blob/e7b7c1648474b22d3f49422d5f818a5b03b208ff/src/backends/meta-input-settings.c#L1890)表明，如果 `remember-numlock-state` 为 false，则 `numlock-state` 设置根本不会被触及，查询函数将直接返回默认值 false。

若要阻止 GDM 更新 `numlock-state` 的值（强制一个确定的 numlock 状态），用 [GNOME 指南](https://help.gnome.org/system-admin-guide/dconf-lockdown.html)所述的方式创建一个 `locks` 目录并锁定该键，所述：

```
/etc/dconf/db/gdm.d/locks/numlock
```

```
/org/gnome/desktop/peripherals/keyboard/numlock-state
```

然后运行以下命令：

```
# dconf update
```

这是一种通用方法，也同样适用于 Wayland 上的 GDM。

### Xfce

在 `~/.config/xfce4/xfconf/xfce-perchannel-xml/keyboards.xml` 中确保以下值设定为 true:

```
<property name="RestoreNumlock" type="bool" value="true"/>
```

> **注意：**如果文件不存在，可以通过**设置** > **键盘** 中的**启动时恢复数字按键状态**进行配置，它会自动创建 `keyboards.xml`。


### SLiM


### OpenBox


### LightDM

参见 [LightDM#NumLock on by default](../../06_软件与应用/Canonical/LightDM.md#NumLock_on_by_default).

### LXDM

```

```

### LXQt

## 默认快捷键

### 内核（SysRq）

以下是系统底层的快捷键，通常被用于调试。遇到系统问题，请尽可能尝试这些快捷键，而不是按住电源开关强制关机。

详情参见 [Magic SysRq key - Wikipedia](https://en.wikipedia.org/wiki/Magic_SysRq_key)。

#### 启用

[systemd](../../01_安装与包管理/初始化/Systemd.md) 有一个[默认设置为 0x10](https://github.com/systemd/systemd/blob/main/sysctl.d/50-default.conf#L14-L19) 的 SysRq 权限掩码。这使得 SysRq [并不能允许进程做发出信号、重启等事项](https://docs.kernel.org/admin-guide/sysrq.html)。为使用 `SysRq` 的完整功能，在 [sysctl#配置 sysctl](../../02_系统管理与内核/内核/Sysctl.md#配置_sysctl)中加入 `kernel.sysrq = 1`。高于 1 的值用于选择性地开启 SysRq 功能，详见 [Linux 内核文档](https://docs.kernel.org/admin-guide/sysrq.html)。如果你想确保其在分区挂载前开启，在[内核参数](../../02_系统管理与内核/内核/内核参数.md)中加入 `sysrq_always_enabled=1`。

注意，改变上述设置将使这些快捷键在重启后保持开启。如果你只想在当前会话开启 SysRq，你可以执行 `sysctl kernel.sysrq=1` 或 `echo "1" > /proc/sys/kernel/sysrq`。

完全启用 SysRq 有明显的安全风险。除了强制重启，它还可以被用来丢弃 CPU 寄存器的内容，理论上来说可以泄露敏感信息。由于使用它需要物理访问系统(除非您通过 [sysrqd](https://github.com/jd/sysrqd) 对外开放)，大多数桌面用户可能认为风险水平是可以接受的。尽管如此，在开启 SysRq 之前，你仍需要确保充分理解开启它的风险。

#### 重启

记住这个激活命令的通用口诀是 "**R**eboot **E**ven **I**f **S**ystem **U**tterly **B**roken" (或者"REISUB")。 要是记不住，想象 "BUSIER" 吧。

> **注意：**千万注意："REISUB" 只是个口诀，决非是一种取得某个死机的系统后门权限的方法。你不应该在不了解这些键的真正功能的情况下盲目按。

| 键盘快捷键 | 描述 |
| --- | --- |
| `Alt`+`SysRq`+`r` **Unraw** | 从X收回对键盘的控制 |
| `Alt`+`SysRq`+`e` **Terminate** | 向所有进程发送SIGTERM信号，让它们正常终止 |
| `Alt`+`SysRq`+`i` **Kill** | 向所有进程发送SIGKILL信号，强制立即终止 |
| `Alt`+`SysRq`+`s` **Sync** | 将待写数据写入磁盘 |
| `Alt`+`SysRq`+`u` **Unmount** | 卸载所有硬盘然后重新按只读模式挂载 |
| `Alt`+`SysRq`+`b` **Reboot** | 重启 |

#### 杀死内存占用过多的进程

`Alt+SysRq+f` 可用于唤醒 [OOM（内存耗尽） 杀手](https://docs.kernel.org/admin-guide/mm/concepts.html?highlight=oom#oom-killer)。即使在没有可以杀死的进程下，这也不会造成内核恐慌。这个 OOM 杀手作出一系列尝试，来杀死相对不重要的进程并收回内存。当某个进程用太多内存，比如浏览器脚本运行失控，导致系统软锁的时候，这很有用，能缓解很多需要重启的情况。请注意，OOM 杀手能杀掉各种进程。尽管其本意是好的，但还是不可预测。因此，要小心使用,不要随意唤醒它。

#### 远程使用

[sysrqd](https://aur.archlinux.org/packages/sysrqd/)AUR 是一个远程使用 `SysRq` 的守护进程。它看起来没人维护了。

#### 疑难解惑

- SysQq 将其结果输出到内核缓存环，会被 systemd 日志收集。即使 [Linux 控制台](../../07_开发与工具/Linux%20控制台/Linux%20控制台.md)没有输出任何东西，结果仍然在内核缓存环中。没有控制台输出并不意味着它没执行成功。如果碰上了这种情况，运行 `journalctl -kf` 来监控其到达内核缓存环的输出。
- 如果你在使用[显示管理器](../../05_桌面与图形/图形用户界面/显示管理器.md)，并且在按下 `Alt+SysRq+e` 后显示了登录界面（开启了自动登录的话，还可能是完全的桌面），这很有可能是由于与[服务文件](../../01_安装与包管理/初始化/Systemd.md)有关的 `Restart=always` 指令导致的。有必要的话，你可能需要编辑单元文件，但这应该不影响 "REISUB" 序列工作。
- 如果以上快捷键除了 `Alt+SysRq+b` 都成功了，尝试使用对测的 `Alt` 键。
- 对于一些用 `Fn` 键从 `PrtScrn` 键中区别出 `SysRq` 键的笔记本，可能并不需要同时按下 `Fn` 键（例如：`Alt+PrtScrn+字母` 可能可以工作）。
- 对于 Legion 系列以外的联想笔记本，经常将 `Fn+S` 设置为 `SysRq` 键。为了使用这个快捷键的功能，先持续按下 `Alt` 键，然后按 `Fn+S`，**松开** `Fn` 与 `s`，始终保持 `Alt` 键，按先前提到的顺序继续按。
- 你可能需要和 `Alt` 一同按下 `Ctrl`。如果这样，完整的快捷键示例就像 `Ctrl+Alt+SysRq+b`。

## 自定义快捷键

### Readline

[Readline](../../07_开发与工具/命令行/Readline.md) 是行编辑领域常用的库，用例见 [Bash](../../07_开发与工具/命令行解释器/Bash.md)、FTP，以及很多的其他软件（详见 [readline](https://archlinux.org/packages/?name=readline)包 包页面下“被依赖”节）。它提供 [Emacs](../../07_开发与工具/Emacs/Emacs.md) 与 [vi](../../07_开发与工具/文本编辑器/Vi.md) 风格的编缉模式，因而有很多可以自定义的空序列。默认快捷键在 [readline(3)](https://man.archlinux.org/man/readline.3) 和[文档页](https://tiswww.cwru.edu/php/chet/readline/rluserman.html)（或 `info readline`）列出。

### Zsh

[Zsh](../../07_开发与工具/命令行解释器/Zsh.md) 使用 [ZLE](../../07_开发与工具/命令行解释器/Zsh.md#Key_bindings) 将快捷键映射到小部件、脚本与指令。

### Xorg

Xorg/Keyboard configuration#Frequently used XKB options 记载了一些常见的快捷键，但它们默认关闭。

在桌面环境下，我们可以通过几种办法来实现一个按键序列被按下的时候自动执行一个指令（例如：将一个指令绑定到 *keysym*）：

- 最可移植的办法是使用低级工具，例如 [acpid](../../02_系统管理与内核/电源管理/Acpid.md)。不是所有的键位都受到支持，但是它也可能通用于键盘案件、电源键甚至耳机接口的插拔事件。但，仍然要注意：它可能很难在 X 会话上正确地运行程序。
- 最普遍的方法是使用 [Xorg](../../05_桌面与图形/X%20服务器/Xorg.md) 工具（如 xbindkeys）和桌面环境（窗口管理器）的工具。
- 快速的办法是用第三方程序，把所有的东西都放到 GUI，例如 Gnome 控制中心。

#### sxhkd

简单的 X 热键守护进程，提供了又小又强的配置语法。详见 [sxhkd](../键盘配置/Sxhkd.md)。

#### actkbd

根据 [actkbd 的主页](http://users.softlab.ece.ntua.gr/~thkala/projects/actkbd/)：

: [actkbd](https://aur.archlinux.org/packages/actkbd/)AUR 是一个简单的将事件绑定到键盘事件上的守护进程。它可以识别组合键、连击、按下与释放按键的事件。它只支持 linux-2.6 edev 介面。它使用富文本的配置档案来记录所有的绑定.

配置示例和指南可以访问[这个链接](http://users.softlab.ece.ntua.gr/~thkala/projects/actkbd/latest/README)。

#### xbindkeys

xbindkeys 支持独立于桌面环境的键-事件映射。

> **提示：**如果你觉得 `xbindkeys` 很难用，有一个图形化的管理器 [xbindkeys_config-gtk2](https://aur.archlinux.org/packages/xbindkeys_config-gtk2/)AUR 可用。

### X-selection-paste 的键位映射

> [![](https://wiki.archlinuxcn.org/wzh/images/d/d6/Tango-inaccurate.png)](https://wiki.archlinuxcn.org/wzh/File:Tango-inaccurate.png)**本文或本章节的事实准确性存在争议。**
>
> **原因：** `Shift+Insert` 从主缓存粘贴（在 [Talk:快捷键](https://wiki.archlinuxcn.org/wiki/Talk:%E5%BF%AB%E6%8D%B7%E9%94%AE) 中讨论）


更喜欢使用键盘工作的用户可能希望用快捷键来替代用中键粘贴，特别是在键盘中心的环境中使用的时候。一个工作流示例如下：

1.  在使用火狐的时候，用鼠标选择一个你想在网上搜索的字符串。
2.  按下 `Ctrl+k` 进入“搜索引擎”区。
3.  按 `F9` 来粘贴缓冲区中的内容，代替用鼠标移到搜索引擎区再按中键。

> **注意：**`Shift+Insert` 的功能很相似，但是略有不同，见[#Xorg](#Xorg)：`Shift+Insert` 在 QT 环境下从剪贴版缓冲区而非 x-selection-paste 缓冲区粘贴。在一些程序中，此二者互相映射。

如上示例使用以下三样包：

- [xsel](https://archlinux.org/packages/?name=xsel)包 来访问 x-selection 缓冲区内容。
- Xbindkeys 来将快捷键绑定到行为。
- [xvkbd](https://aur.archlinux.org/packages/xvkbd/)AUR 用于通过模拟键盘输入来将缓冲区中的字符串输入到应用中。

这个示例将 x-selection 粘贴操作绑定到 `F9` 键：

```
.xbindkeysrc
```

```
"xvkbd -no-jump-pointer -xsendevent -text "\D1`xsel`" 2>/dev/null"
    F9
```

`"\D1"` 码前置 100 毫秒延迟来插入到选定的缓冲区（详见 [xvkbd 主页](http://t-sato.in.coocan.jp/xvkbd/)）。

> **注意：**取决于你的 X 设置，你可能需要不在 xvkbd 使用 `--xsendevent` 参数。

除了 `F9` 以外的键也可以用 `xbindkeys -k` 绑定。
