> 本章解决“装得上、放不出、用不顺”的多媒体问题：声音归 PipeWire 与 WirePlumber 管，能不能播取决于编解码器与容器，图形、三维、截屏录屏则各有专用软件。
> 
> 先读 PipeWire、编解码器与容器这两节，再用故障排除补洞，WirePlumber 顺带过一遍配置。图形工具与屏幕捕获按需翻查，示例可跳过。最容易踩的坑是把 PipeWire 与 WirePlumber 混为一谈，或以为装了软件就能播放——缺编解码器时往往只是没声音、打不开，屏幕捕获在 Wayland 下的表现也常被误判成软件坏了。

## 3.1　Inkscape

*难度：入门 ｜ 篇幅：2.2 KB ｜ 所属：多媒体*

将要讲到：安装、疑难问题解决、参见

[Inkscape](https://inkscape.org/) 是矢量图形创建和编辑程序。它是根据自由软件许可 GNU GPL 分发的。其既定目标是成为功能强大的图形工具，同时完全符合 XML、SVG 和 CSS 标准。

## 安装

[inkscape](https://archlinux.org/packages/?name=inkscape)包 可以从[官方储存库](../../00_关于与社区/关于%20Arch/官方仓库.md)安装。开发版本可以从 [AUR](../../00_关于与社区/关于%20Arch/Arch%20用户软件仓库.md) 安装 [inkscape-git](https://aur.archlinux.org/packages/inkscape-git/)AUR。

## 疑难问题解决

### KDE Plasma 环境无法显示工具提示

在 KDE 的系统设置下，找到 颜色 > 选项，然后禁用“将颜色应用于非 QT 应用程序”。如果更改之前正在运行 Inkscape，请重新启动 Inkscape。

### 空格键和鼠标不起作用

默认情况下, 输入时 [libinput](../../04_硬件与外设/输入设备/Libinput.md) 禁用了 mousepad。你可以修改此设置，在 `/etc/X11/xorg.conf.d/30-touchpad.conf`的 `InputClass` 部分添加一行新内容:

```
Section "InputClass"
    ...
    ...
    Option "DisableWhileTyping" "0"
EndSection
```

### 无法修改键盘快捷键

为了能够更改键盘快捷方式，请创建可以编辑的快捷方式文件的副本：

```
mkdir -p ~/.config/inkscape/keys
cp /usr/share/inkscape/keys/default.xml ~/.config/inkscape/keys/
```

之后请重新启动 Inkscape。

## 3.2　火焰截图

*难度：进阶 ｜ 篇幅：5.9 KB ｜ 所属：多媒体*

将要讲到：安装、问题解决、参见

[火焰截图（Flameshot）](https://flameshot.org)是一款屏幕截图工具。该程序提供了交互式图形界面及多种控制功能，用户可选取指定捕获区域、移动并调整捕获窗口尺寸、使用常见绘图工具（铅笔、直线、矩形、圆形、模糊（像素化）、撤销/重做）进行编辑，并选择输出方式（复制到剪贴板、保存至磁盘、上传至 [Imgur](https://imgur.com)、通过其他程序打开）。

## 安装

安装 [flameshot](https://archlinux.org/packages/?name=flameshot)包 软件包。若需开发版本，可安装 [flameshot-git](https://aur.archlinux.org/packages/flameshot-git/)AUR。

## 问题解决

### 子命令立即退出而无输出

在 X 会话期间随时将火焰截图作为后台进程启动：

```
$ flameshot &
```

### 无托盘图标

可通过多种方式解决，此处提供一种方案：

安装 [gnome-shell-extension-topicons-plus](https://aur.archlinux.org/packages/gnome-shell-extension-topicons-plus/)AUR。

然后在 GNOME Tweaks 应用程序中（若未安装需先下载）：

1.  点击“扩展”选项卡。
2.  启用“Topicons plus”以将传统托盘图标移至顶部面板。
3.  完成！

### 火焰截图无法识别当前可见窗口

若安装了 [xf86-video-intel](https://archlinux.org/packages/?name=xf86-video-intel)包 可能出现此问题。

移除 [xf86-video-intel](https://archlinux.org/packages/?name=xf86-video-intel)包 软件包，并确保 `/etc/X11/xorg.conf.d/` 目录下无该软件包的残留 X11 配置。

随后重启系统。

此问题曾在火焰截图 GitHub 仓库讨论：。

### Wayland 下火焰截图选区操作卡顿

[PR #2766](https://github.com/flameshot-org/flameshot/pull/2766) 导致在 Wayland 中选择截图区域时出现严重卡顿。该问题正在 [issue #3039](https://github.com/flameshot-org/flameshot/issues/3039) 中追踪，[PR #3059](https://github.com/flameshot-org/flameshot/pull/3059) 可能包含修复方案。临时解决方案是使用无此问题的 12.1.0-1 版本。

### Sway/wlroots 环境下火焰截图启动报错

截图时可能显示以下错误：

```
flameshot: error: Unable to capture screen
flameshot: error: Unable to capture screen
qt.qpa.wayland: Wayland does not support QWindow::requestActivate()
flameshot: info: Screenshot aborted.
```

需安装以下软件包使火焰截图在 Wayland 下正常工作：

[xdg-desktop-portal](https://archlinux.org/packages/?name=xdg-desktop-portal)包、[xdg-desktop-portal-wlr](https://archlinux.org/packages/?name=xdg-desktop-portal-wlr)包、[grim](https://archlinux.org/packages/?name=grim)包。

安装完成后即可正常启动火焰截图。

更多信息请参阅 [Sway 维基页面](https://github.com/flameshot-org/flameshot/blob/master/docs/Sway%20and%20wlroots%20support.md)。

### 火焰截图在 KDE Plasma Wayland 多显示器环境下只能在单个屏幕生效

火焰截图覆盖层仅在单个显示器显示。GitHub 仓库中有人建议了[解决方案](https://github.com/flameshot-org/flameshot/issues/3073#issuecomment-1740187784)。

基本思路是用 KDE Plasma 配置覆盖火焰截图叠加窗口的初始位置，这样火焰截图叠加窗口才能显示在所有连接的显示器上。为此，启动“窗口规则”应用程序，并创建一个新的窗口规则，设置如下：

- **窗口类 (应用程序)**：flameshot
- **窗口类型**：正常窗口
- **窗口标题**：完全匹配：flameshot
- **位置**：强制 0x0
- **全屏**：强制 否
- **遵守大小和位置限制**：强制 是
- **窗口置顶**：强制 是

### 火焰截图在 Sway 的多显示器环境下只能在单个屏幕生效

火焰截图覆盖层仅在单个显示器显示。GitHub 仓库中有人建议了[解决方案](https://github.com/flameshot-org/flameshot/issues/2364#issuecomment-1086129055)。

该解决方案的核心是强制火焰截图窗口/覆盖层以浮动模式启动，而不是全屏模式。可以在 Sway 配置文件中添加以下行来实现：

```
for_window [app_id="flameshot"] border pixel 0, floating enable, fullscreen disable, move absolute position 0 0
```

另外，也可以强制 Flameshot 运行在 XWayland 模式下：

```
QT_QPA_PLATFORM=xcb flameshot gui
```

但需要注意，此方法虽然修复了多显示器问题，但会导致键盘快捷键失效，导致火焰截图只能通过鼠标操作。

### 火焰截图在 KDE Dolphin 中无法生成缩略图

在 Plasma 6 中，使用 Dolphin 文件选择器保存截图时，如果目录中存在其他图片文件，则不会显示缩略图。在终端中运行 Flameshot 时，会看到以下错误信息：

```
kf.service.services: KServiceTypeTrader: serviceType "ThumbCreator" not found
```

安装 [kio5-extras](https://archlinux.org/packages/?name=kio5-extras)包 可解决该问题。

## 3.3　ImageMagick

*难度：进阶 ｜ 篇幅：6.6 KB ｜ 所属：多媒体*

将要讲到：安装、使用方法、用图像创建 PDF、另见

根据[英文维基百科](https://en.wikipedia.org/wiki/ImageMagick)：

: ImageMagick is a free and open-source software suite for displaying, converting, and editing raster image and vector image files. It can read and write over 200 image file formats.

: （译文）ImageMagick 是一款自由及开放源代码的软件套件，用于显示、转换及编辑位图图像和矢量图像文件。它能够读写超过 200 种不同的图像文件格式。

## 安装

安装 [imagemagick](https://archlinux.org/packages/?name=imagemagick)包。或者通过 [graphicsmagick](https://archlinux.org/packages/?name=graphicsmagick)包 安装 [GraphicsMagick](https://en.wikipedia.org/wiki/GraphicsMagick)⸺ImageMagick 的分支，强调 API 和命令行界面的稳定性。

## 使用方法

参见 [ImageMagick(1)](https://man.archlinux.org/man/ImageMagick.1)，或使用 [gm(1)](https://man.archlinux.org/man/gm.1) 查看 GraphicsMagick 的手册页。

> **提示：**安装软件包后，可在本地访问官方 HTML 文档：
>
> - ImageMagick 的文档路径为 `/usr/share/doc/ImageMagick-7/www/index.html`
> - GraphicsMagick 的文档路径为 `/usr/share/doc/GraphicsMagick/www/index.html`

### 常见操作

> **注意：**参数前的符号非常重要。用“+”代替“-”可以执行相反操作。

#### 格式转换

ImageMagick 通过文件扩展名确定格式。例如，要将给定的 *.png* 图像转换为 *.jpg* 格式，需要使用：

```
$ magick 图像.png 图像.jpg
```

#### 拼接

将多张图片拼接为一张：

```
$ magick -append 输入1.png 输入2.png ... 输出.png
```

#### 裁剪与切除

对多张图像进行裁剪并转换格式：

```
$ mogrify -crop 宽x高+X+Y -format jpg *.png
```

其中*宽*和*高*表示裁剪后的输出图像尺寸，*X* 和 *Y* 表示相对于输入图像的偏移量。

也可使用 `-chop`，通过 -gravity 参数切除指定单侧边框，这种方式无需复杂坐标计算，操作更简便：

```
$ magick 红色边框.gif -gravity South -chop 0x10 切除底部.gif
```

#### 限制文件大小

在指定文件大小下获得合理画质：

```
$ magick 图像.jpg -define jpeg:extent=3000KB 压缩图像.jpg
```

这有助于缩短传输时间。注意 `-quality` 参数（如以下用法：）

```
$ magick 图像.jpg -quality 85% 压缩图像.jpg
```

当画质与文件大小的对应关系不明确时难以使用。

### 截屏

使用 [import(1)](https://man.archlinux.org/man/import.1) 命令便捷截取当前系统屏幕：

```
$ import -window root screenshot.jpg
```

若不带 `-window` 参数运行 `import`，可交互式地选择窗口或其它任意区域。使用 `-pause` 参数设置延时，在此期间可执行操作（例如最小化某些窗口）。

> **注意：**若需使用 **graphicsmagick** 的等效功能，只需在命令前添加 "gm"，例如 `$ gm import -window root screenshot.jpg`。

#### 在 X11 中进行多屏幕截屏

若使用双屏模式（twinview）或双头输出（dualhead），可分别截取两个屏幕后再使用 imagemagick 拼接：

```
$ import -window root -display :0.0 -screen /tmp/0.png
$ import -window root -display :0.1 -screen /tmp/1.png
$ convert +append /tmp/0.png /tmp/1.png 截屏.png
$ rm /tmp/{0,1}.png
```

#### 使用 Xinerama 时截取单个物理屏幕

使用 Xinerama 进行的多显示器配置仅存在单个虚拟屏幕。当物理屏幕高度不一致时，截图会产生无效区域。此时可单独截取每个物理屏幕（需确保 X 服务器提供 Xinerama 信息）：

```
#!/bin/sh
xdpyinfo -ext XINERAMA | sed '/^  head #/!d;s///' |
while IFS=' :x@,' read i w h x y; do
        import -window root -crop ${w}x$h+$x+$y 显示屏$i.png
done
```

#### 对活动（焦点所在）窗口截屏

以下脚本可截取当前活动窗口，适用于支持 EWMH（NetWM）的 X 窗口管理器。为了避免覆盖之前的截图，此处将当前日期用作文件名。

```
#!/bin/sh
activeWinLine=$(xprop -root | grep "_NET_ACTIVE_WINDOW(WINDOW)")
activeWinId=${activeWinLine:40}
import -window "$activeWinId" /tmp/$(date +%F_%H%M%S_%N).png
```

另外，无论是否支持 EWMH，以下方法应该都可行：

```
$ import -window "$(xdotool getwindowfocus -f)" /tmp/$(date +%F_%H%M%S_%N).png
```

> **注意：**如果某些程序（例如 zathura（英语：[zathura](https://wiki.archlinux.org/title/zathura)））的截图显示为空白，请尝试在 `xdotool` 命令后添加 `-frame` 或移除 `-f`。

### 加密图像数据

加密方法：

```
$ echo 密码词组 | magick 图像.jpg -encipher - -depth 8 png24:图像.png
```

解密方法：

```
$ echo 密码词组 | magick 图像.png -decipher - 图像.jpg
```

有关此类命令可能遇到的各种问题及优化建议（如加密后文件格式的指定），参见官方文档 [Encrypting Image Data](https://usage.imagemagick.org/transform/#encipher)。

一些图像格式的元数据支持 `cipher` 标签，可用于检测图像是否加密，但该标签可能被 EXIF 编辑工具移除或伪造。

```
$ identify -verbose image.png
```

通用的检测方法可通过分析像素分量分布实现：若其熵值超过特定阈值，数据可视为随机（即可能经过加密）。但需注意[菱形平方算法](https://en.wikipedia.org/wiki/Diamond-square_algorithm)生成的图像也会产生类似特征，属于典型误判案例。

## 控制工具

> **提示：**为常用控制命令和多媒体键，（如`XF86AudioPlay`, `XF86AudioStop`, `XF86AudioPrev` 与 `XF86AudioNext`）创建[键绑定](../../04_硬件与外设/键盘/快捷键.md)

### Playerctl

[playerctl](https://archlinux.org/packages/?name=playerctl)包 工具提供了一个命令行工具，用于将命令发送到 MPRIS 客户端。最常见的命令是 `play-pause`, `next` 与 `previous`:

```
$ playerctl play-pause
$ playerctl next
$ playerctl previous
```

*playerctl* 会向它找到的第一个播放器发送命令。要手动选择播放器，请使用 `--player` 选项，例如 `--player=vlc` 。为了更好地实现自动化，playerctl 附带了一个守护进程，它能跟踪媒体播放器的活动，并将命令发送给最近有活动的播放器。你可以使用以下命令将它转入后台：

```
$ playerctld daemon
```

为了在登录时启动 *playerctld*，您可以创建以下 [systemd/用户](../../02_系统管理与内核/系统管理/Systemd_用户.md)服务

```
~/.config/systemd/user/playerctld.service
```

```
[Unit]
Description=Keep track of media player activity

[Service]
Type=oneshot
ExecStart=/usr/bin/playerctld daemon

[Install]
WantedBy=default.target
```

然后，您应该在启用带有`--user`标志的服务之前执行[daemon-reload](https://wiki.archlinuxcn.org/wzh/Help:%E9%98%85%E8%AF%BB#控制_systemd_单元) 。

> **提示：**可以安装 [playerctld-systemd-unit](https://aur.archlinux.org/packages/playerctld-systemd-unit/)AUR 软件包，而不是手动创建服务。

此外，*playerctld* 还能够更改*活动*播放器，这在您同时拥有多个媒体流时非常有用：

要切换到下一个播放器，请使用：

```
$ playerctld shift
```

要切换到上一个播放器，请使用：

```
$ playerctld unshift
```

### mpris-player-control

[mpris_player_control](https://gitlab.com/axdsop/nix-dotfiles/tree/master/Configs/polybar/scripts/mpris_player) 是一个 shell 脚本，它集成了 `dbus-send` 和 `pactl` 以控制 MPRIS 客户端。它支持播放、暂停、暂停播放和停止操作，以及 Spotify 的音量控制（静音/静音/上/下）。

运行 `mpris_player_control -h` 以显示基本脚本用法。

### D-Bus

上述方法的替代方法是手动使用 [D-Bus](../../02_系统管理与内核/系统管理/D-Bus.md)，默认情况下它应该可用，因为它是 [systemd](../../01_安装与包管理/初始化/Systemd.md) 的依赖项。

例如，可以使用以下命令通过支持的 [Methods](https://specifications.freedesktop.org/mpris-spec/latest/Player_Interface.html#methods) 来控制 Spotify：

```
$ dbus-send --print-reply --dest=org.mpris.MediaPlayer2.spotify /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2.Player.Method
```

类似地，使用 [busctl(1)](https://man.archlinux.org/man/busctl.1):

```
$ busctl --user call org.mpris.MediaPlayer2.spotify /org/mpris/MediaPlayer2 org.mpris.MediaPlayer2.Player Method
```

> **注意：**某些耳机（例如索尼 WH-1000XM3）提供 AVRCP 接口。对于这些类型，不需要 *mpris-proxy* 。只需确保已为媒体键设置了[键绑定](../../04_硬件与外设/键盘/快捷键.md)即可。

```

```

[Service]
Type=simple
ExecStart=/usr/bin/mpris-proxy

[Install]

```

然后，在启动/启用带有`--user` 标志的服务之前执行[daemon-reload](https://wiki.archlinuxcn.org/wzh/Help:%E9%98%85%E8%AF%BB#控制_systemd_单元)。

> **提示：**可以安装 [mpris-proxy-service](https://aur.archlinux.org/packages/mpris-proxy-service/)AUR 软件包，而不是手动创建服务。

## 3.5　GStreamer

*难度：进阶 ｜ 篇幅：8.9 KB ｜ 所属：多媒体*

[GStreamer](https://en.wikipedia.org/wiki/GStreamer) 是一个基于管道的多媒体框架。Gstreamer使用C语言编写，基于GObject。

Gstreamer允许程序员创建各种媒体处理组件，包括简单的音频播放，音频与视频播放，录制，流媒体控制与媒体编辑。其管道式设计是创建多种多媒体程序的基础，例如视频编辑器，流媒体服务器，以及媒体播放器。

Gstreamer是跨平台框架，目前已知可在下列平台上工作：Linux (x86, PowerPC 以及 ARM), Solaris (Intel 和 SPARC), Mac OS X, Microsoft Windows 以及 OS/400。GStreamer 提供了多种编程语言的绑定，包括 Python、C++、Perl、GNU Guile（guile）和 Ruby。GStreamer 是自由软件，采用 GNU宽通用公共许可证（LGPL）授权。。

## GPU 渲染

Blender支持大多数硬件加速渲染。在根据你的硬件准备好系统（见下文）后，你可以在*编辑 > 偏好设置... > 系统*中选择显卡作为渲染设备。

在本文撰写之时，你可能需要为Blender指定一个额外的[环境变量](../../02_系统管理与内核/系统管理/环境变量.md)：

CYCLES_ONEAPI_ALL_DEVICES=1 blender
```

对于支持的GPU而言 (GFX9, CDNA, 以及 RDNA, 详情请参考[官方的硬件兼容列表](https://docs.blender.org/manual/en/latest/render/cycles/gpu_rendering.html#hip-amd))，安装[hip-runtime-amd](https://archlinux.org/packages/?name=hip-runtime-amd)包来通过HIP获得Blender的GPU加速功能，使用[Mesa](../../07_开发与工具/开发/OpenGL.md)驱动。

> **注意：**ROCm HIP目前在3D视角中使用cycles渲染引擎存在[问题](https://gitlab.freedesktop.org/drm/amd/-/issues/2145)（参考"问题"中的内容来获得解决方法），但是通过 *渲染 > 渲染图像* 或按下F12渲染图像工作正常

## 专业的渲染插件

Blender在专业领域以及工业上越来越知名。因此，目前已有不少EEVEE和Cycles渲染引擎的替代品，它们以插件的形式存在。以下列出了在Linux上发布或者即将发布的专业渲染插件列表。

### BlendNet

[BlendNet](https://github.com/state-of-the-art/BlendNet) 是一个开源的插件，它能让多台机器上的CPU和GPU协作渲染。

BlendNet内置了对主要云服务的支持，例如AWS, Azure 或者 GCP, 而且也支持您自己的渲染农场。

#### 集成云服务器

1.  安装软件包 [blendnet](https://aur.archlinux.org/packages/blendnet/)AUR。
2.  在*偏好设置 -> 插件 -> Render: BlendNet* 中启用BlendNet插件
3.  按照官方[BlendNet wiki](https://github.com/state-of-the-art/BlendNet/wiki)的指引，配置好AWS、Azure或GCP上的渲染农场

#### 自建服务器

[blendnet](https://aur.archlinux.org/packages/blendnet/)AUR 提供了systemd单元和配置，这让您能便利地部署您自己的CUDA GPU加速的Blendnet渲染农场。

BlendNet渲染农场由一个“管理员”实例与多个代理机器组成。 blender插件连接到管理员，借此安排渲染作业。 参看 [BlendNet wiki](https://github.com/state-of-the-art/BlendNet/wiki/How-BlendNet-is-working) 以了解更多和BlendNet架构有关的内容。

首先，请在管理员、代理和安装插件的机器上都安装好 [blendnet](https://aur.archlinux.org/packages/blendnet/)AUR，然后按照以下步骤执行。

##### 设置: 管理员

1.  复制`/etc/blendnet/server.key`和`/etc/blendnet/server.crt`到所有管理员、代理和安装插件的机器上的`/etc/blendnet/`目录.
2.  编辑`/etc/blendnet/manager.json`，添加管理员用户名和密码。
3.  编辑`/etc/blendnet/manager.json`，添加代理用户名和密码。
4.  启动/启用`blendnet-manager.service`服务。

##### 设置: 代理

1.  编辑`/etc/blendnet/agent.json`添加和管理员机器中相同的代理用户名和密码。
2.  启动/启用`blendnet-agent.service`服务。

如果安装来[cuda](https://archlinux.org/packages/?name=cuda)包，[blendnet](https://aur.archlinux.org/packages/blendnet/)AUR会自动启用GPU+CPU加速：你可以通过查看代理机器的日志来检查GPU加速是否启用：

```
$ journalctl -xefu blendnet-agent.service
```

##### 设置: 插件

1.  在*偏好设置 -> 插件 -> Render: BlendNet* 中启用BlendNet插件。
2.  为插件配置管理员/代理的用户名和密码。
3.  指定`/etc/blendnet/server.crt`中的CA证书。
4.  关闭偏好设置，打开渲染属性并启用Cycles渲染引擎 （**不是**BlendNet！）
5.  通过"BlendNet Render (local)"的Cycles面板中`+`添加所有代理。
6.  根据[BlendNet 渲染说明](https://github.com/state-of-the-art/BlendNet/wiki/HOWTO%3A-First-steps#run-the-first-render-task)完成剩余步骤。

### LuxCoreRender

## 解决问题

### Blender在选择对象时会很卡顿

当使用集成Intel显卡时，可能要5-10秒才能选择一个对象。在*File > User Preferences > System* 中将 *Selection* 改为 *OpenGL Occlusion Queries*。

### Blender未把AMD显卡列在OpenCL渲染设备中


Blender（目前）仅支持AMD官方专有驱动来启用OpenCL，意味着你需要安装以下任意一个AMD OpenCL驱动：

- [AMDGPU PRO](../../05_桌面与图形/图形/AMDGPU%20PRO.md)
- [opencl-amd](https://aur.archlinux.org/packages/opencl-amd/)AUR驱动搭配开源AMDGPU驱动

安装后AMD GPU应该会出现在渲染设备中，通过 *File > User Preferences > System > Compute Device* 选择。

> **注意：**Blender开发者决定转移到其他API([HIP](https://github.com/ROCm-Developer-Tools/HIP))并弃用OpenCL支持。该决定将会在Blender 3.0生效（2021年12月4日），参见[更多内容](https://developer.blender.org/T91571)。

### Blender 在 i915 上崩溃

仅仅更改初始界面中的立方体大小，就会导致Blender无响应，dmesg显示关于GPU挂起的信息：

```
kernel: i915 0000:00:02.0: [drm] blender context reset due to GPU hang
kernel: i915 0000:00:02.0: [drm] GPU HANG: ecode 9:1:85df9ebf, in blender 
```

解决办法来源于[上游Bug](https://gitlab.freedesktop.org/drm/intel/-/issues/2935)和一个[AskUbuntu上的提问](https://askubuntu.com/questions/1477715/blender-hangs-using-intel-integrated-graphics):

- 设置`INTEL_DEBUG=reemit`环境变量后启动Blender,也就是说将Blender .desktop文件的Exec行内容改为`Exec=env INTEL_DEBUG=reemit blender %f`

- 增加preemtion超时限制到 10 000 ms。要永久改变这个值，添加一个[udev](../../04_硬件与外设/硬件检测和故障排除/Udev.md)规则：

```
/etc/udev/rules.d/99-i915-increase-preemt-timeout.rules
```

```
# Increase Intel preemt timeout to 10 000 ms
#
# This is needed for Blender not to crush, see
# https://askubuntu.com/questions/1477715/blender-hangs-using-intel-integrated-graphics

ACTION=="add|bind",SUBSYSTEM=="pci",DRIVER=="i915",RUN+="/bin/bash -c 'for i in /sys/$DEVPATH/drm/card?/engine/[rc]cs*/preempt_timeout_ms; do echo 10000 > $i; done'"
```

如果字体过小或模糊，字体大小可以通过*User Preferences > Themes > Text Style*增加（一或两磅）。在*User Preferences > Themes > System*选择加粗字体作为界面字体可以明显降低模糊。

## 3.7　WirePlumber

*难度：进阶 ｜ 篇幅：16.8 KB ｜ 所属：多媒体*

将要讲到：安装、配置、提示与技巧、故障排除、参见

[WirePlumber](https://pipewire.pages.freedesktop.org/wireplumber) 是一款强大的[PipeWire](PipeWire.md) 会话和策略管理器。其采用模块化设计，使用 Lua 插件进行管理，具有高度可配置性及可扩展性。

## 安装

安装 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包。任何冲突的 PipeWire 会话管理器会被卸载。

WirePlumber 使用 systemd [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)管理 PipeWire 服务。

## 配置

### 配置文件布局

[WirePlumber 的配置](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration.html)使用 PipeWire 的 JSON 对象如 `context` 和 `alsa_monitor`，通过修改这些对象来控制其行为。配置文件位于 `~/.config/wireplumber/`（用户配置）、`/etc/wireplumber/`（全局配置）以及 `/usr/share/wireplumber/`（默认配置）。

WirePlumber 启动时首先会读取[主配置文件](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/conf_file.html)。这是一个类 JSON 文件，用于设定 PipeWire 上下文环境（context）、[SPA 插件](https://docs.pipewire.org/page_spa_plugins.html)、模块以及组件。

默认配置文件位于 `/usr/share/wireplumber/wireplumber.conf`，其是一个单实例配置文件，集成其他配置到一个进程中。请参阅文档 [ALSA 对象](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/alsa.html)、["access" 对象](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/access.html)和[蓝牙对象](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/bluetooth.html)。

### 修改配置

推荐向 `/etc/wireplumber/` 或 `~/.config/wireplumber/` 目录下的 `wireplumber.conf.d/` 文件夹内添加 [SPA-JSON](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/conf_file.html#the-spa-json-format) 文件来配置 WirePlumber。

用户配置较系统配置具有更高优先级，低优先级的同名配置文件会被忽略。在配置目录中，各文件按照字母数字顺序被读取，请参阅[文档](https://pipewire.pages.freedesktop.org/wireplumber/daemon/locations.html#config-locations)以了解详细信息。

### 获取用于规则匹配的接口名称

在配置文件中，需要指定 `matches` 规则，并使用要配置的接口对应[对象](https://docs.pipewire.org/page_objects_design.html)的某项属性进行匹配。

使用 `wpctl status` 命令显示 WirePlumber 管理的所有对象。找到分配给目标接口的 `*ID*`，然后运行 `wpctl inspect *ID*` 获取所需的属性。

例如，如果目标接口是 `HD Audio Controller Analog Stereo`，可以参考以下输出：

```
$ wpctl status
```

```
PipeWire 'pipewire-0' [0.3.56, user@hostname, cookie:1163266174]

Audio
 ├─ Devices:
 │      42. HD Audio Controller                 [alsa]
 │     105. USB PnP Audio Device                [alsa]
 │
 ├─ Sinks:
 │  *   48. HD Audio Controller Analog Stereo   [vol: 0.50]
 │
 ├─ ...
 │
 ├─ Sources:
 │  *  101. USB PnP Audio Device Mono           [vol: 0.74]
 │
 └─ ...
```

该接口的 `*ID*` 为 `48`。

接下来使用 inspect 命令查看该对象的详细信息及其全部属性：

```
$ wpctl inspect 48
```

```
id 48, type PipeWire:Interface:Node
    ...
    device.api = "alsa"
    device.class = "sound"
  * device.id = "42"
    device.profile.description = "Analog Stereo"
    device.profile.name = "analog-stereo"
    ...
  * factory.id = "18"
    factory.mode = "merge"
    factory.name = "api.alsa.pcm.sink"
    ...
  * media.class = "Audio/Sink"
  * node.description = "HD Audio Controller Analog Stereo"
  * node.name = "alsa_output.pci-0000_08_00.4.analog-stereo"
  * node.nick = "ALC1220 Analog"
    ...
  * object.path = "alsa:pcm:1:front:1:playback"
  * object.serial = "49"
    ...
```

请选择具有唯一性且稳定的属性用于 `matches` 规则。推荐使用 `device.name` 或 `node.name` 属性。

避免使用 `device.id`，因为它是动态分配的，可能在不同会话之间发生变化。

规则支持正则表达式和多个属性的 `matches` 匹配；详情参见[官方文档](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/modifying_configuration.html#working-with-rules)中的“Working with rules”一节。

> **注意：**
>
> - 对大多数用户来说，有两种重要的对象类型：
> - **Device** 对象相当于一个 *ALSA 声卡*（ALSA Card）。
> - **Node** 对象相当于一个 *ALSA 设备*（ALSA Device）。
> - [PipeWire 虚拟设备](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Virtual-Devices)的流类别由 `media.class` 属性指示。分类逻辑参见 [WirePlumber 链接策略简介](https://pipewire.pages.freedesktop.org/wireplumber/policies/linking.html#introduction)。
> - WirePlumber 使用 PCM 名称填充 `node.nick` 属性。在使用 UCM 的 HDA 声卡上，即使模拟输出、HDMI 等不同输出共用同一个配置文件，也能将它们作为独立的 `Nodes` 暴露出来，并为其提供有描述性的昵称。

> **提示：**
>
> - 如果难以找到目标接口，可以使用 PipeWire 命令 `pw-top` 查看当前处于活动状态的 `devices` 和 `nodes` 列表。
> - PipeWire 中类似的检查命令是 `pw-cli info *ID*`。

### 修改设备／节点属性

要修改设备或节点的属性，例如描述或昵称，需要创建一个 [SPA-JSON](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/conf_file.html#the-spa-json-format) 文件，并按照正确的路径和文件名将其放在 `/etc/wireplumber/` 或 `~/.config/wireplumber/` 下。

例如，要修改 ALSA 节点的描述，可以创建如下文件：

```
/etc/wireplumber/wireplumber.conf.d/device-rename.conf（或 ~/.config/wireplumber/wireplumber.conf.d/device-rename.conf）
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        node.name = "alsa_output.pci-0000_00_1f.3.output_analog-stereo"
      }
    ]
    actions = {
      update-props = {
        node.description = "Laptop"
      }
    }
  }
]
```

如果要修改蓝牙节点或设备的属性，可以创建如下文件：

```
/etc/wireplumber/wireplumber.conf.d/bluez-rename.conf（或 ~/.config/wireplumber/wireplumber.conf.d/bluez-rename.conf）
```

```
monitor.bluez.rules = [
  {
    matches = [
      {
        node.name = "bluez_output.02_11_45_A0_B3_27.a2dp-sink"
      }
    ]
    actions = {
      update-props = {
        node.nick = "Headphones"
      }
    }
  }
]
```

可修改的属性以及用于选择设备或节点的匹配规则，详见 [ALSA 配置](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/alsa.html)和[蓝牙配置](https://pipewire.pages.freedesktop.org/wireplumber/daemon/configuration/bluetooth.html)文档。

### 禁用设备／节点

任何设备或节点都可以被禁用：对于设备，设置 `device.disabled` 属性；对于节点，设置 `node.disabled` 属性：

```
/etc/wireplumber/wireplumber.conf.d/alsa-disable.conf（或 ~/.config/wireplumber/wireplumber.conf.d/alsa-disable.conf）
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        device.name = "alsa_card.pci-0000_08_00.4"
      }
    ]
    actions = {
      update-props = {
         device.disabled = true
      }
    }
  }
]
```

按照[#获取用于规则匹配的接口名称](#获取用于规则匹配的接口名称)中的说明，找到设备或节点的唯一标识符。 本例使用 `device.name` 进行匹配，也可以使用 `node.nick` 等其他标识属性。

> **注意：**请注意，如果匹配的是节点属性而非设备属性，就必须使用 `node.disabled`，而不是 `device.disabled`。

一种常见用途是禁用显卡的 HDMI 音频输出。 这种方式也可以通过匹配特定节点（例如 `node.nick`）来只禁用指定显示器的 HDMI 音频，因为该属性可能随连接的设备而变化。

### 设置节点优先级

要改变自动选择的音频输出节点（sink）或输入节点（source），需要设置其 `priority.session` 值：

```
/etc/wireplumber/wireplumber.conf.d/set-priorities.conf
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        node.name = "alsa_output.usb-Generic_USB_Audio-00.HiFi__Speaker__sink"
      }
    ]
    actions = {
      update-props = {
        priority.session = 100
      }
    }
  }
]
```

本例将华硕 B650E-F 主板板载音频的扬声器输出节点优先级从原来的 1000 降至 100。这样，其他具有更高优先级的输出节点，例如板载音频设备的 S/PDIF 输出或已连接的耳机，就会被选为默认输出，而不是模拟扬声器输出。

需要注意，默认情况下，优先级的实际影响可能比预期更小。WirePlumber 在计算机启动或设备拔出时，默认会优先恢复之前选择过的设备。若要让这些情况下的选择遵循优先级，应禁用对先前选择的记忆：

```
/etc/wireplumber/wireplumber.conf.d/no-restore-default.conf
```

```
wireplumber.settings = {
   node.restore-default-targets = false
}
```

### 同一声卡上的多个输出节点同时输出

参见 [PipeWire/故障排除#同一声卡同时向多个音频输出设备输出](PipeWire_故障排除.md#同一声卡同时向多个音频输出设备输出)。

### 向临时连接的设备同时输出

你可能希望同时向板载设备和外部设备输出声音，即使外部设备并非始终连接。 为实现这一点，我们先创建一个始终存在的虚拟节点，使其不受硬件是否连接的影响。然后，每当临时设备（本例为 USB 耳机）接入时，就将其连接至该虚拟节点。

首先，创建一个在登录时运行的脚本。通常最简单的方式是使用窗口管理器的启动项功能。

```
/usr/local/bin/create-virtual-sink.sh
```

```
#!/bin/bash

# Create a new sink called Simultaneous Output
pw-cli create-node adapter '{ factory.name=support.null-audio-sink node.name="Simultaneous Output" node.description="Simultaneous Output" media.class=Audio/Sink object.linger=true audio.position=[FL FR] }'

# Connect the normal permanent sound card output to the new sink
pw-link "Simultaneous Output:monitor_FL" alsa_output.pci-0000_05_04.0.analog-stereo:playback_FL
pw-link "Simultaneous Output:monitor_FR" alsa_output.pci-0000_05_04.0.analog-stereo:playback_FR

# Switch the default output to the new virtual sink
wpctl set-default `wpctl status | grep "\. Simultaneous Output" | egrep '^ │( )*[0-9]*' -o | cut -c6-55 | egrep -o '[0-9]*'`
```

在上面的示例中，最初唯一的输出设备是“普通”板载声卡（alsa_output.pci-0000_05_04.0.analog-stereo）。可以运行 `wpctl status` 和 `wpctl inspect` 来确定自己声卡的标识符。

插入 USB 耳机时，运行以下脚本，将耳机连接到虚拟输出节点：

```
link-virtual-sink-headphones.sh
```

```
#!/bin/bash
# link the virtual sync to your headphones should run when detected by UDEV

# wait a second for the drivers to load
sleep 1s

# link the headphones to your virtual sink
sudo -u user1 env XDG_RUNTIME_DIR=/run/user/1000 pw-link "Simultaneous Output:monitor_FL" alsa_output.usb-Kingston_HyperX_Cloud_Flight_S_000000000001-00.analog-stereo:playback_FL
sudo -u user1 env XDG_RUNTIME_DIR=/run/user/1000 pw-link "Simultaneous Output:monitor_FR" alsa_output.usb-Kingston_HyperX_Cloud_Flight_S_000000000001-00.analog-stereo:playback_FR

# finish and return the code for success
exit 0
```

理想情况下，应在耳机插入时自动运行该脚本。[udev](../../04_硬件与外设/硬件检测和故障排除/Udev.md) 页面介绍了如何为此创建自定义规则。（不过要注意，不能直接通过 udev 运行此脚本，因为 udev 要在指定脚本执行*之后*才会加载驱动程序。因此需要使用中间脚本，并借助 nohup 等方式间接启动。） 此外，需要修改上述脚本，使 XDG_RUNTIME_DIR 与自己的用户 ID 对应，并将 **user1** 替换为自己的用户名。

可以用相同的方法将任意数量的设备添加到这个虚拟输出节点。

如果难以弄清各设备之间的连接关系，可以使用 [qpwgraph](https://archlinux.org/packages/?name=qpwgraph)包 工具，以图形方式直观查看设备之间的连接。

## 提示与技巧

### 删除损坏的设置

如果 WirePlumber 的设置损坏，可以删除所有用户设置。先停止 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)，再使用以下命令删除设置：

```
$ rm -r ~/.local/state/wireplumber
```

然后可以重新启动 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

### 键盘控制音量

参见 [快捷键#Xorg](../../04_硬件与外设/键盘/快捷键.md#Xorg)，了解如何将以下命令绑定到音量按键：`XF86AudioRaiseVolume`、`XF86AudioLowerVolume`、`XF86AudioMute` 和 `XF86AudioMicMute`。

提高音量，上限为 150%：

```
$ wpctl set-volume -l 1.5 @DEFAULT_AUDIO_SINK@ 5%+
```

降低音量：

```
$ wpctl set-volume @DEFAULT_AUDIO_SINK@ 5%-
```

静音／取消静音：

```
$ wpctl set-mute @DEFAULT_AUDIO_SINK@ toggle
```

将麦克风静音／取消静音：

```
$ wpctl set-mute @DEFAULT_AUDIO_SOURCE@ toggle
```

> **提示：**如果要操作的不是默认输出或输入节点，可以运行 `wpctl status` 列出所有可用的输出节点，并使用相应的输出或输入节点编号替换 `@DEFAULT_AUDIO_SINK@` 或 `_SOURCE@`。

### 显示音量级别

查看默认输出节点的音量级别和静音状态：

```
$ wpctl get-volume @DEFAULT_AUDIO_SINK@
```

```
Volume: 0.45
```

> **注意：**只有在输出节点处于静音状态时，才会显示静音状态。

### 禁用蓝牙配置文件自动切换

参见 [PipeWire#自动化 profile 切换](PipeWire.md#自动化_profile_切换)。

### 注销后保持蓝牙运行／无头蓝牙

> **注意：**还需要为运行 [PipeWire](PipeWire.md)/WirePlumber 的用户启用 [用户驻留](../../02_系统管理与内核/系统管理/Systemd_用户.md#随系统自动启动_systemd_用户实例)。

自 0.4.8 版本起，需要禁用 BlueZ 座席监控（seat-monitoring）对 `support.logind` 的要求。

```
~/.config/wireplumber/wireplumber.conf.d/disable-logind.conf
```

```
wireplumber.profiles = {
  main = {
    monitor.bluez.seat-monitoring = disabled
  }
}
```

### 禁用音频栈集成

如果你打算使用另一套音频解决方案（例如 [PulseAudio](../../04_硬件与外设/声音/PulseAudio.md)、[JACK](../../04_硬件与外设/声音/JACK%20Audio%20Connection%20Kit.md) 或 [ALSA](../../04_硬件与外设/声音/ALSA.md)），不希望 [PipeWire](PipeWire.md)/WirePlumber 接管音频设备，但仍希望保留其屏幕共享或视频相关功能，可以使用 `wireplumber@.service` [模板单元](../../01_安装与包管理/初始化/Systemd.md#使用单元)启用另一组默认配置文件。WirePlumber 提供了一个仅启用视频相关部分、禁用音频集成（包括蓝牙音频）的配置文件，可以通过启用 `video-only` 模板[用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)使用它。

禁用 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)，并启用 `wireplumber@video-only.service` 用户单元。

### 调整当前未播放音频的应用程序音量

有些应用程序（例如启动器）发声时间太短，无法使用图形混音器及时调整音量。WirePlumber 将每个应用程序和每个节点的音量及静音状态保存在文本文件 `$HOME/.local/state/wireplumber/stream-properties` 中。可以手动编辑该文件以修改设置。编辑时请确保 WirePlumber *没有*运行，否则它可能会覆盖所做的修改。

## 3.8　编解码器与容器

*难度：进阶 ｜ 篇幅：17.0 KB ｜ 所属：多媒体*

将要讲到：需求、编解码器列表、容器格式工具、后端、疑难解答

自维基百科[Wikipedia](https://en.wikipedia.org/wiki/Codec), "**编解码器**（英语：codec）指的是一个能够对一个信号或者一个数据流进行编解码操作的设备或者程序。."

一般来说，编解码器被多媒体应用程序用来对音频或视频流进行编码或解码。为了播放编码后的数据流，用户必须确保安装了适当的编解码器。

这篇文章只关于编解码器及程式后端；见[List of applications/Multimedia](../应用程序/应用程序列表_多媒体.md) 以列举音视频播放器的选择如([MPlayer](../视频/MPlayer.md), [mpv](../../03_网络与服务/串流/Mpv.md) 和 [VLC](../../03_网络与服务/串流/VLC%20媒体播放器.md))

## 需求

播放常见的媒体需要

- 一个播放器
- 一个编解码器

如果有了媒体播放器，不一定非要安装编解码器。例如，[MPlayer](../视频/MPlayer.md) 就内置了大量编解码器。

## 环绕声系统

### 分离前置与后置声道

当[使用 PipeWire 替代 PulseAudio/JACK](PipeWire.md#声音) 时，你可以配置 PipeWire 来复制 PulseAudio 的前置/后置分离示例。这样一来，你就可以将使用 PulseAudio 的音频流发送到扬声器或耳机的独立输出端（Sink）。

将扬声器连接到线路输出（line-out）端口，耳机连接到后置端口。在 `pavucontrol` 中将所使用的声卡设置为 Analog Surround 4.0 Output。

#### 使用 PipeWire 配置文件

创建额外的 PipeWire 配置文件 `~/.config/pipewire/pipewire.conf.d/speakers-headphones.conf` 或 `/etc/pipewire/pipewire.conf.d/speakers-headphones.conf`，写入以下内容并根据实际情况修改 `target.object` 行：

```
context.modules = [
    {   name = libpipewire-module-loopback
        args = {
            node.name = "speakers"
            node.description = "Speakers"
            capture.props = {
                media.class = "Audio/Sink"
                audio.position = [ FL FR ]
            }
            playback.props = {
                target.object = "alsa_output.pci-0000_00_14.2.analog-surround-40"
                stream.dont-remix = true
                node.passive = true
                audio.position = [ FL FR ]
            }
        }
    }
    {   name = libpipewire-module-loopback
        args = {
            node.name = "headphones"
            node.description = "Headphones"
            capture.props = {
                media.class = "Audio/Sink"
                audio.position = [ FL FR ]
            }
            playback.props = {
                target.object = "alsa_output.pci-0000_00_14.2.analog-surround-40"
                stream.dont-remix = true
                node.passive = true
                audio.position = [ RL RR ]
            }
        }
    }
]
```

重启 PipeWire 后，你应该会在 `pavucontrol` 中看到两个新的输出。类似的示例可以在 \[[1]([https://docs.pipewire.org/page_module_loopback.html](https://docs.pipewire.org/page_module_loopback.html)) PipeWire Loopback 模块文档\]中找到。

如果你使用的是 [pipewire-pulse](https://archlinux.org/packages/?name=pipewire-pulse)包，你可能还需要通过编辑 `~/.config/pipewire/pipewire-pulse.conf` 或在 `/etc/pipewire/pipewire-pulse.conf.d/` 中创建配置文件来启用上混音（upmixing）：

```
stream.properties = {
   channelmix.upmix = true
   channelmix.upmix-method = psd # none, simple
   channelmix.lfe-cutoff = 150
   channelmix.fc-cutoff = 12000
   channelmix.rear-delay = 12.0
}
```

这些选项及更多的解释可以通过以下命令查看：

```
$ man pipewire-props
```

#### 使用 `pactl` 和 `pw-link`

使用以下命令为扬声器和耳机创建新的输出端，并将扬声器链接到前置声道、将耳机链接到后置声道：

```
 pactl load-module module-null-sink sink_name=speakers object.linger=1 media.class=Audio/Sink channel_map=FL,FR
 pactl load-module module-null-sink sink_name=headphones object.linger=1 media.class=Audio/Sink channel_map=RL,RR
```

`object.linger=1` 可以使输出端在创建它的客户端断开连接后保持存活。你可以将 `sink_name` 命名为任意名称。

要卸载模块，你可以使用 `pw-cli destroy ID`，其中 `ID` 是 `pactl load-module` 命令的输出。目前暂不支持通过 `pactl unload-module` 单独卸载模块 \[[2]([https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/709](https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/709))\]。不过，你可以使用 `pactl unload-module module-null-sink` 来卸载所有 `module-null-sink` 模块。

使用 `jack_connect`，将新输出端的监听器连接到声卡的播放端口。通过运行 `pw-link -iol` 来查明声道的名称 \[[3]([https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Migrate-JACK](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Migrate-JACK))\]。

```
 pw-link speakers:monitor_1 alsa_output.pci-0000_00_14.2.analog-surround-40:playback_FL
 pw-link speakers:monitor_2 alsa_output.pci-0000_00_14.2.analog-surround-40:playback_FR
 pw-link headphones:monitor_1 alsa_output.pci-0000_00_14.2.analog-surround-40:playback_RL
 pw-link headphones:monitor_2 alsa_output.pci-0000_00_14.2.analog-surround-40:playback_RR
```

> **提示：**将上述命令加入脚本并[自动启动](../../02_系统管理与内核/系统管理/自动启动.md)以实现流程自动化。请务必将 `alsa_output.pci-0000_00_14.2.analog-surround-40` 替换为你声卡的名称。在脚本执行前添加延迟也可能会使运行更加平稳。

> **注意：**Jack/Pipewire 的输出端名称似乎不时会发生变化。在上面的示例中，`alsa_output.pci-0000_00_14.2.analog-surround-40:playback_FL` 有时会变成 `Built-in\ Audio\ Analog\ Surround\ 4.0:playback_FL`。作为临时变通方法，你可以在自动启动脚本中添加第二套使用备用名称的 `pw-jack` 命令。

要单独控制音量，一种选择是使用 [ALSA](../../04_硬件与外设/声音/ALSA.md) 工具（例如 [amixer(1)](https://man.archlinux.org/man/amixer.1)）来控制 *Front*（前置）和 *Rear/Surround*（后置/环绕，ALSA 命名）声道。可以在\[[4]([https://gist.github.com/nicman23/a2a80200e1d5d1f65b75846c5f2387b7](https://gist.github.com/nicman23/a2a80200e1d5d1f65b75846c5f2387b7)) 此处\]找到一个根据当前默认 PulseAudio 输出端自动执行该操作的脚本。

## 回声消除

PipeWire 可以实时从麦克风中去除扬声器的声音，这使得在不使用耳机的情况下参与语音聊天成为可能，*甚至在其他应用程序正在播放音频时也是如此*。

通常，语音聊天应用程序确实会消除回音，但它们只能识别经过自身的音频。例如，如果另一个语音聊天参与者通过你的扬声器讲话，聊天应用程序会“感知”到这一点，并能够选择性地从你的麦克风中擦除这种噪声，否则该噪声会作为烦人的回声被重复发送回语音聊天中。这种方法的弊端通常在于*其他应用程序*通过你的扬声器播放音频时——因为语音聊天无法感知这些音频，其他参与者可能会听到并抱怨。示例如下：

- 在使用独立语音聊天应用程序的同时玩网络视频游戏
- 在使用语音聊天应用程序的同时使用同步视频播放解决方案，例如 Jellyfin SyncPlay 或 Watch2Gether

这就是系统级回声消除所要解决的问题；你不再让语音聊天应用去抑制回声（且在上述情况下会失效），而是让 PipeWire 来完成，它能够天然地“感知”扬声器上播放的*所有*音频。

假设 PipeWire 采用默认配置，可以通过在 `/etc/pipewire/pipewire.conf.d/` 中创建一个以“.conf”结尾且世界可读的配置文件来启用系统级回声消除，例如 `60-echo-cancel.conf`：

“aec.args”的默认值可以在 \[[5]([https://gitlab.freedesktop.org/pipewire/pipewire/-/blob/master/spa/plugins/aec/aec-webrtc.cpp](https://gitlab.freedesktop.org/pipewire/pipewire/-/blob/master/spa/plugins/aec/aec-webrtc.cpp)) 此处\]找到，只需在 “aec-webrtc.cpp” 中搜索 “webrtc.” 即可。

```
context.modules = [

     # 回声消除
     {   name = libpipewire-module-echo-cancel
         args = {
             # 监听模式：PipeWire 的回声消除模块不创建所有应用程序都必须播放的虚拟输出端，
             # 而是直接从当前的默认（fallback）音频输出读取需要消除的音频
             monitor.mode = true
             capture.props = {
                 node.name = "ec_capture"
                 node.description = "Echo-cancellation capture"
                 media.name = "Echo-cancellation capture"
                 # 要从中消除回声的音频源/麦克风
                 # 可以通过以下命令查找：pw-cli list-objects Node | grep node.name
                 # 可选；如果未指定，模块将使用/跟随默认音频源
                 #node.target = "alsa_input.usb-UGREEN_Camera_UGREEN_Camera_SN0001-02.analog-stereo"
                 # 被动节点：当此捕获空闲时，不要使麦克风保持活动状态
                 node.passive = true
                 # 强制图中的输入流量子（quantum）
                 # 如果遇到语音失真/爆音，可以调整此项
                 # 默认：0/未设置
                 #node.force-quantum = 256
             }
             # 要从输入中过滤掉的输出端
             # 可以通过以下命令查找：pw-cli list-objects Node | grep node.name
             # 可选；如果未指定，模块将使用/跟随默认音频源
             #sink.props = {
             #   node.target = "alsa_output.pci-0000_0f_00.4.analog-stereo"
             #}
             source.props = {
                 # 提供消除回声后的麦克风音频的虚拟音频源
                 node.name = "source_ec"
                 node.description = "Echo-cancellation source"
                 media.name = "Echo-cancellation source"
             }
             aec.args = {
                 # WebRTC 回声消除引擎的设置
                 # 增益控制：动态麦克风音频归一化
                 # 默认：false
                 # 注意，PipeWire WebRTC 源代码建议不要启用它：
                 #  > 注意：AGC 似乎会干扰无关延迟检测（Agnostic Delay Detection），特别是
                 #  > 对于语音，会导致非常差的性能，默认禁用
                 #webrtc.gain_control = true
                 # 扩展滤波器：放宽音频延迟窗口（？）
                 # 默认：true
                 # 引用已废弃的 Mozilla Positron 项目（2016年）的旧源码：
                 #  > 扩展滤波器模式使我们能够灵活地忽略系统报告的延迟。
                 #  > 我们对那些我们认为其提供结果与 AEC 期望不符的平台这样做。
                 # 建议：除非必要，否则将其关闭
                 webrtc.extended_filter = false
             }
         }
     }
 ]
```

诸如此类的配置更改需要 重启 PipeWire（即 `pipewire.service` 和 `pipewire-pulse.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)）才能生效。

## 语音处理

通过在滤波器链（filter chain）模块中使用均衡器（EQ）、高通滤波器、除嘶声器（de-esser）和压缩器，可以提高电容麦克风的语音清晰度。

安装 [lsp-plugins-lv2](https://archlinux.org/packages/?name=lsp-plugins-lv2)包 和 [calf](https://archlinux.org/packages/?name=calf)包。在 `~/.config/pipewire/pipewire.conf.d/` 中创建一个 `.conf` 文件（或者修改你存放滤波器链模块的配置文件），使用以下模板：

```
context.modules = [{
   name = libpipewire-module-filter-chain
   args = {
       filter.graph = {
           nodes = [
               # 高通滤波器 - 消除约 80Hz 以下的喷麦低频杂音
               {
                   type   = builtin
                   name   = hp
                   label  = bq_highpass
                   control = {
                       "Freq"  = 90
                       "Q"     = 0.707
                   }
               }
               # 除嘶声器 (LSP)
               {
                   type    = lv2
                   plugin  = "[6](http://calf.sourceforge.net/plugins/Deesser)"
                   name    = deesser
                   control = {
                       detection = 0       # 0=RMS, 1=Peak
                       mode      = 1       # 0=Wide, 1=Split
                       threshold = 0.18    # ~ -15 dB 线性值
                       ratio     = 4.0
                       laxity    = 15
                       f1_freq   = 6500.0   # "Split" 分频点
                       f2_freq   = 6500.0   # "Peak" 检测中心
                   }
               }
               # 语音均衡器 (Calf)
               {
                   type    = lv2
                   plugin  = "[7](http://calf.sourceforge.net/plugins/Equalizer5Band)"
                   name    = eq
                   control = {
                       ls_active = 1
                       ls_freq   = 100.0
                       ls_level  = 0.668    # -3 dB，减少低频浑浊感
                       p1_active = 1
                       p1_freq   = 300.0
                       p1_q      = 1.0
                       p1_level  = 0.794    # -2 dB，减少箱声/盒音
                       p2_active = 1
                       p2_freq   = 3000.0
                       p2_q      = 1.0
                       p2_level  = 1.259    # +2 dB，增加临场感
                       hs_active = 1
                       hs_freq   = 9000.0
                       hs_level  = 0.708    # -3 dB，修饰高频刺耳声
                   }
               }
               # 压缩器 (Calf)
               {
                   type    = lv2
                   plugin  = "[8](http://calf.sourceforge.net/plugins/Compressor)"
                   name    = comp
                   control = {
                       threshold = 0.125    # ~ -18 dB 线性值
                       ratio     = 3.0
                       attack    = 10.0
                       release   = 100.0
                       makeup    = 1.585    # ~ +4 dB 线性值
                   }
               }
           ]
           # 这可以与 PipeWire wiki 页面上详细介绍的降噪插件结合使用，
           # 只需取消下面 links[] 行的注释并更改输入即可
           links = [
               #{ output = "rnnoise:Output"  input = "gate:Input" }
               #{ output = "gate:Output"     input = "hp:In" }
               { output = "hp:Out"          input = "deesser:in_l" }
               { output = "deesser:out_l"   input = "eq:in_l" }
               { output = "eq:out_l"        input = "comp:in_l" }
           ]
           #inputs = [ "rnnoise:Input" ]
           inputs = [ "hp:In" ]
           outputs = [ "comp:out_l" ]
       }
       capture.props = {
           node.name             = "capture.voice_processing"
           node.description    = "Voice processing capture"
           media.name          = "Voice processing capture"
           node.passive        = true
           audio.rate          = 48000
           audio.position      = [ FL ]
           # 如果与上面的降噪示例结合使用，请使用
           # node.target 来指定输入，而不是使用定位到输入默认源的 stream.capture.sink
           #node.target         = "source_ec"
           stream.capture.sink = true
       }
       playback.props = {
           node.name             = "voice_processing_source"
           node.description    = "Voice processing source"
           media.name          = "Voice processing source"
           media.class         = "Audio/Source"
           audio.rate          = 48000
           audio.position      = [ FL ]
       }
   }
}]
```

要调整各种插件的数值，请使用电压/振幅分贝（dB）公式：`linear = 10^(dB / 20)`

## 将附加音频混入麦克风音频中

为实现这一点，你需要额外加载两个“Combine stream”（合并流）模块实例，如下所示。

             combine.mode = sink
             node.name = sink_fx
             node.description = "Effects sink (play shared audio here)"
             combine.props = {
                 audio.position = [ FL FR ]
             }
             stream.props = {
                 # 如果你在 client.conf.d 中有上混音配置，请在此处设置相同的
                 # 参数，否则你的音效应用程序将不会在本地音频输出中被上混音

                 #combine.audio.position = [ FL FR FL FR ]

             }
         }
     }

     # 主源（Main source）

     #  - sink_fx.monitor（音频效果输出端的监听器）
     {   name = libpipewire-module-combine-stream

             combine.mode = source
             node.name = source_main
             node.description = "Main source (record from here)"

             combine.props = {
                 audio.position = [ FL FR ]
             }
             stream.rules = [
                 {   matches = [
                         {
                             node.name = "source_ec"
                             media.class = "Audio/Source"
                         }
                     ]
                     actions = {
                         create-stream {
                         }
                     }
                 }
                 # TODO 包含匹配和动作的块，用于匹配 sink_fx 的监听器并将其连接到 source_main
                 # 目前尚无自动化此操作的已知 PipeWire 配置

                 # [10](https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/3710)
                 # 目前，请在 Helvum 中手动添加所需的连接，即连接这些点：

             ]
         }
     }
 ]
```

## 将音频流传输到 Android 设备

可在 Android 上使用的 \[[11]([https://github.com/kaytat/SimpleProtocolPlayer](https://github.com/kaytat/SimpleProtocolPlayer)) Simple Protocol Player\] 应用程序可以通过 \[[12]([https://docs.pipewire.org/page_module_protocol_simple.html](https://docs.pipewire.org/page_module_protocol_simple.html)) PipeWire 简单协议\]接收音频流。这允许将主机上的音频播放通过 TCP 路由到 Android 设备。

创建一个 PipeWire 配置文件 `~/.config/pipewire/pipewire.conf.d/android-streaming.conf`，内容如下：

```
context.modules = [
     {
         name = libpipewire-module-protocol-simple
         args = {
             # 启用捕获模式（向外发送音频）
             capture = true
             playback = false

             # 音频格式设置
             audio.rate = 48000
             audio.channels = 2

             # TCP 地址和端口
             # 替换为 Android 设备的 IP 地址
             server.address = [
                 "tcp:12345"
             ]

             capture.props = {
                 # 替换为你的输出设备名称
                 # 可通过以下命令查找：pw-cli list-objects Node | grep node.name
                 target.object = "alsa_output.usb-Creative_Technology_Ltd_SB_X-Fi_Surround_5.1_Pro_0000007E-00.analog-stereo"
                 stream.capture.sink = true
             }
         }
     }
 ]
```

重启 PipeWire 以应用配置。在 Android 设备上，打开 Simple Protocol Player 应用并连接到配置端口上的主机 IP 地址。

> **注意：**TCP 连接是未加密且未经身份验证的。请仅在受信任的网络上使用此功能。

#### maim

[maim](https://archlinux.org/packages/?name=maim)包 旨在成为 scrot 的改进版。

截取全屏并保存至文件：

```
$ maim 文件名
```

交互式选择矩形区域，截取后保存至文件：

```
$ maim --select 文件名
```

截取当前活动窗口并保存至文件（需安装 [xdotool](https://archlinux.org/packages/?name=xdotool)包）：

```
$ maim --window $(xdotool getactivewindow) 文件名
```

选区截屏（不包含光标）并存入剪贴板（需安装 [xclip](https://archlinux.org/packages/?name=xclip)包）：

```
$ maim -s | xclip -selection clipboard -t image/png -i
```

#### scrot

[scrot](https://archlinux.org/packages/?name=scrot)包 支持通过命令行截图，并提供自定义延时等功能。默认将文件保存在当前工作目录。

```
$ scrot -t 20 -d 5
```

上述的命令会在 5 秒延时后保存一个带日期的 .png 文件及一个适用于网页发布的缩略图（大小为原图的 20%）。

也可使用标准日期时间格式保存，例如使用命令

```
$ scrot ~/截屏/%Y-%m-%d-%T-截屏.png
```

将截图以包含年-月-日-时间的文件名保存至主目录的“截屏”文件夹。

详见 [scrot(1)](https://man.archlinux.org/man/scrot.1)。

> **注意：**在某些窗口管理器（如 [dwm](https://aur.archlinux.org/packages/dwm/)AUR、[xmonad](https://archlinux.org/packages/?name=xmonad)包）中，通过快捷键直接运行 `scrot -s` 时选区功能可能异常，可通过添加短暂延时解决：`sleep 0.2; scrot -s`。

#### 其他桌面环境/窗口管理器

对于 [LXDE](../../05_桌面与图形/LXDE/LXDE.md) 等桌面环境或 [Openbox](../../05_桌面与图形/堆叠式窗口管理器/Openbox.md)、[Compiz](../../05_桌面与图形/堆叠式窗口管理器/Compiz.md) 等窗口管理器，可通过添加快捷键调用截图命令。例如：

```

```
rc.xml
```

```
<!-- Screenshot -->
    <keybind key="Print">
      <action name="Execute">
        <command>sh -c "import -window root ~/Pictures/$(date '+%Y%m%d-%H%M%S').png"</command>
      </action>
    </keybind>
```

若上述的 `PrintScreen` 键无法使用，请参阅[键盘输入](../../04_硬件与外设/键盘配置/键盘输入.md)使用不同的键符（keysym）或键码（keycode）。

## Wayland

要在基于 Wlroots 的混成器上捕获屏幕，截屏可以使用 [grim](https://archlinux.org/packages/?name=grim)包 或来自 [sway-contrib](https://archlinux.org/packages/?name=sway-contrib)包 中的 grimshot；录屏可以使用 [wf-recorder](https://archlinux.org/packages/?name=wf-recorder)包（或 [wf-recorder-git](https://aur.archlinux.org/packages/wf-recorder-git/)AUR）。[obs-studio](https://archlinux.org/packages/?name=obs-studio)包 的插件 [wlrobs-hg](https://aur.archlinux.org/packages/wlrobs-hg/)AUR 可用于支持在基于 Wlroots 的合成器上进行屏幕捕捉。可选使用 [slurp](https://archlinux.org/packages/?name=slurp)包 选择截屏区域。如果 GPU 支持 [vaapi](../../05_桌面与图形/图形/硬件视频加速.md) 编码，[wl-screenrec-git](https://aur.archlinux.org/packages/wl-screenrec-git/)AUR 可以作为 [wf-recorder](https://archlinux.org/packages/?name=wf-recorder)包 的更高效替代方案。

对整个屏幕截屏：

```
$ grim 截屏.png
```

在 Sway 中对当前窗口截屏：

```
$ swaymsg -t get_tree | jq -r '.. | select(.focused?) | .rect | "\(.x),\(.y) \(.width)x\(.height)"' | grim -g - 截屏.png
```

在 [Hyprland](../../05_桌面与图形/Wayland%20合成器/Hyprland.md) 中对当前窗口截屏：

```
$ hyprctl -j activewindow | jq -r '"\(.at),\(.at) \(.size)x\(.size)"' | grim -g - 截屏.png
```

对选区截屏：

```
$ slurp | grim -g - 截屏.png
```

对选区截屏并使用 [wl-clipboard](https://archlinux.org/packages/?name=wl-clipboard)包 将结果存入剪贴板：

```
$ slurp | grim -g - - | wl-copy
```

对整个屏幕录屏：

```
$ wf-recorder -f recording.mp4
```

对选区录屏：

```
$ wf-recorder -g "$(slurp)"
```

> **提示：**
>
> - 使用 [bemenu](https://archlinux.org/packages/?name=bemenu)包 的交互式脚本 [slurpshot](https://github.com/de-arl/slurpshot) 可用于截图。
> - 可以在截屏后使用截屏编辑工具，如 [swappy](https://archlinux.org/packages/?name=swappy)包：`grim -g "$(slurp)" -` 。

> **提示：**
>
> - [screenshot.sh](https://gist.github.com/mrhdias/b97bf99c92cb9fc9bac49590d4603ec5) 是 Wayland 下的 GUI 截图工具，使用 [zenity](https://archlinux.org/packages/?name=zenity)包、[grim](https://archlinux.org/packages/?name=grim)包 和[slurp](https://archlinux.org/packages/?name=slurp)包。

此外，部分前文提到的程序也支持在Wayland环境下工作，例如 [ksnip](https://archlinux.org/packages/?name=ksnip)包 和 [green-recorder](https://aur.archlinux.org/packages/green-recorder/)AUR。

#### 使用虚拟摄像头推流

参见 v4l2loopback#使用 wf-recorder 投射 Wayland 屏幕（英语：[v4l2loopback#Casting Wayland using wf-recorder](https://wiki.archlinux.org/title/v4l2loopback#Casting_Wayland_using_wf-recorder)）。

> **提示：**
>
> - 此方法已在 [zoom](https://aur.archlinux.org/packages/zoom/)AUR（桌面客户端，运行于 [xorg-xwayland](https://archlinux.org/packages/?name=xorg-xwayland)包）和 [chromium](https://archlinux.org/packages/?name=chromium)包 中运行的 [BigBlueButton](https://bigbluebutton.org/)（在 [firefox](https://archlinux.org/packages/?name=firefox)包 中分辨率极低）测试通过；[skypeforlinux-bin](https://aur.archlinux.org/packages/skypeforlinux-bin/)AUR 能检测到虚拟视频设备 `VirtualVideoDevice`，但输出黑屏。
> - 示例使用 `wf-recorder`，也可以用其他软件，只需将输出导向虚拟设备即可。

安装 [wf-recorder](https://archlinux.org/packages/?name=wf-recorder)包（或 [wf-recorder-git](https://aur.archlinux.org/packages/wf-recorder-git/)AUR）和 [v4l2loopback-dkms](https://archlinux.org/packages/?name=v4l2loopback-dkms)包。指定以下参数加载 `v4l2loopback` 内核模块：

```
# modprobe v4l2loopback exclusive_caps=1 card_label=VirtualVideoDevice
```

验证是否已创建名为 `VirtualVideoDevice` 的新虚拟视频设备：

```
$ v4l2-ctl --list-devices
```

```
...
VirtualVideoDevice (platform:v4l2loopback-000):
	/dev/video2
...
```

使用 `wf-recorder` 开始录制屏幕，并将输出导向 `v4l2loopback` 创建的虚拟视频设备 `VirtualVideoDevice`：

```
$ wf-recorder --muxer=v4l2 --codec=rawvideo --file=/dev/video2 -x yuv420p
```

为了确保视频输出与 Zoom 兼容，必须使用 `yuv420p` 色彩空间 。

> **提示：**若遇到 `Unknown V4L2 pixel format equivalent for rgb0` 错误，可在运行 `wf-recorder` 时添加 `--force-yuv` 或 `-t` 参数，强制将数据转换为 yuv 格式后再发送至 GPU 。

然后可以在视频通话/会议应用中选择上述虚拟视频设备作为“摄像头”（设备名为 `VirtualVideoDevice`）。您可使用 `ffplay`（[ffmpeg](https://archlinux.org/packages/?name=ffmpeg)包 的组件）、[mpv](https://archlinux.org/packages/?name=mpv)包 或 `gst-launch`（[gstreamer](https://archlinux.org/packages/?name=gstreamer)包 的组件）验证虚拟设备是否正常输出屏幕内容：

```
$ ffplay /dev/video2
```

```
$ mpv av://v4l2:/dev/video2
```

```
$ gst-launch-1.0 -v v4l2src device=/dev/video2 ! glimagesink
```

若 Firefox 无法读取视频流并显示类似“AbortError: Starting video failed”的信息，可尝试预加载 `v4l2compat.so`：

```
$ LD_PRELOAD=/usr/lib/v4l1compat.so firefox
```

##### 仅共享屏幕的一部分

> **警告：**此方法并不是真正的单个应用程序共享实现，因为所共享的区域在调整窗口大小后不会发生变化。

如上所述，`wf-recorder` 可以通过 [slurp](https://archlinux.org/packages/?name=slurp)包 选择一个区域，从而仅录制屏幕的一部分。要利用此功能向虚拟摄像头发送特定区域/应用程序窗口，可以使用以下修改后的命令开始录制屏幕：

```
$ wf-recorder -g "$(slurp)" --muxer=v4l2 --codec=rawvideo --file=/dev/video2 -x yuv420p
```

在选择屏幕区域后，即可通过虚拟摄像头 `/dev/video2` 访问视频流。

#### 使用 WebRTC 协议

> **注意：**此方法仅允许共享整个屏幕，而不能仅共享屏幕的一部分 。

参见 [PipeWire#WebRTC 屏幕共享](PipeWire.md#WebRTC_屏幕共享)。

Chromium 和 Firefox 现在应该可以访问屏幕共享。可以通过 [Mozilla 的 getUserMedia/getDisplayMedia 测试页面](https://mozilla.github.io/webrtc-landing/gum_test.html)进行验证。

### 通过X11应用程序录制Wayland窗口

### 使用 ANSI 代码捕获

可以使用 [util-linux](https://archlinux.org/packages/?name=util-linux)包 软件包中的 [script(1)](https://man.archlinux.org/man/script.1) 命令。运行 `script` 后，所有终端输出（包括 ANSI 代码）将自动保存至 `typescript` 文件。

```
$ ansi2html --bg=dark < typescript > typescript.html
```

实际上，**部分**命令的输出可直接通过管道传递给 ansi2html：

```
$ ls --color|ansi2html --bg=dark >output.html

## 音量

### 多种应用程序没有声音，但浏览器有声音

> [![](https://wiki.archlinuxcn.org/wzh/images/d/d6/Tango-inaccurate.png)](https://wiki.archlinuxcn.org/wzh/File:Tango-inaccurate.png)**本文或本章节的事实准确性存在争议。**
>
> **原因：** 问题的根本原因仅为猜测，尚未得到验证。是否只是应用程序被静音？（在 [Talk:PipeWire/故障排除](https://wiki.archlinuxcn.org/wiki/Talk:PipeWire/%E6%95%85%E9%9A%9C%E6%8E%92%E9%99%A4) 中讨论）

使用 `mpv` 检查已安装的编解码器是否正常工作：

```
$ mpv --ao=alsa test_file.mpv
$ mpv --ao=pcm test_file.mpv
$ mpv --ao=jack test_file.mpv
$ mpv --ao=pulse test_file.mpv
$ mpv --ao=openal test_file.mpv
```

如果上述部分或全部测试能够发出声音，而以下命令不能：

```
$ mpv --ao=pipewire test_file.mpv
```

则可能是 `pipewire` 通道被静音。安装并运行 `pavucontrol`。

在“配置”选项卡中选择适当的设备，然后在“输出设备”选项卡中再次选中它。在播放 `mpv --ao=pipewire test.mp4` 视频的同时，使用“静音”按钮先静音再取消静音。

或者删除 `~/.local/state/wireplumber/`，再通过 `systemctl --user restart pipewire pipewire-pulse wireplumber.service` 重启 PipeWire。

### 音量过低

将 PulseAudio 替换为 PipeWire 后，声音可能起初正常，但重启后音量变得低得难以接受。

打开 `alsamixer`，按 `F6` 选择正确的声卡，并确保 ALSA 音量为 100%。`alsactl` 应在重启后保留此设置。

### SDDM 和 LightDM 用户登录后设备音量未恢复

如果使用 [SDDM](../../05_桌面与图形/显示管理器/SDDM.md) 或 [LightDM](../Canonical/LightDM.md)，并发现登录后音量未正确恢复，可以屏蔽显示管理器用户的 PipeWire，因为显示管理器账户下运行的 WirePlumber 可能干扰当前用户的 WirePlumber 会话。

```
# systemctl --user -M user@ mask pipewire.socket
```

对于 SDDM，将 `*user*` 替换为 `sddm`；对于 LightDM，则替换为 `lightdm`。

更多详细信息参见[Debian Wiki 文章](https://wiki.debian.org/PipeWire#Device_volume_for_SDDM_users_is_not_restored_on_login)。

## 麦克风

### PipeWire 无法检测麦克风

如果使用笔记本内置麦克风，或通过耳机插孔连接的麦克风，首先确保当前使用的配置文件已启用模拟输入。可以在 [pavucontrol](https://archlinux.org/packages/?name=pavucontrol)包 中（也可能在桌面环境的声音设置中）查看。在 pavucontrol 的“配置”选项卡中，确保“内置音频”（或类似名称）选择了“模拟立体声双工”。如果使用 5.1 声道、HDMI 音频等高级音频配置，请选择包含“+ 模拟立体声输入”的配置文件。

PipeWire 的 `alsa-monitor` 模块默认使用 [alsa-card-profiles](https://archlinux.org/packages/?name=alsa-card-profiles)包 检测设备。如果无法正常工作，尝试禁用 `api.alsa.use-acp`，或者在 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包 中启用 `api.alsa.use-ucm`：

```
/etc/wireplumber/wireplumber.conf.d/alsa-config.conf (or ~/.config/wireplumber/wireplumber.conf.d/alsa-config.conf)
```

```
monitor.alsa.properties = {
  # 使用 ALSA-Card-Profile 设备。它们通过 UCM 或 profile
  # 配置来设置设备和混音器参数。
  # alsa.use-acp = true
  # 如果可用，使用 UCM 代替 profile。也可以禁用此项，
  # 以跳过使用 UCM 配置文件的尝试。
  alsa.use-ucm = true
}
```

使用 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包 时：

```
/etc/pipewire/media-session.d/alsa-monitor.conf (or ~/.config/pipewire/media-session.d/alsa-monitor.conf)
```

```
...
rules = [
    {
        ...
        actions = {
        update-props = {
            ...
            api.alsa.use-acp = false
...
```

随后重启 WirePlumber 并检查可用设备：


```
$ pw-record --list-targets
```

```
Available targets ("*" denotes default): 62
	58: description="Built-in Audio" prio=1872
	60: description="Built-in Audio" prio=2000
*	62: description="Built-in Audio (Loopback PCM)" prio=1984
```

[此 PipeWire 问题报告](https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/2332)还提出了一种替代方案：手动添加麦克风。首先确保 ALSA 已检测到麦克风。

```
$ arecord -l
```

```
**** List of CAPTURE Hardware Devices ****
card card_number: card_name, device device_number: device_name
  ...
```

从列表中选择麦克风，然后运行以下命令进一步测试：

```
$ arecord --duration=5 --format=dat --device=hw:card_number,device_number test-mic.wav # 从麦克风录音
$ aplay test-mic.wav # 播放录音
```

如果麦克风可以通过 `arecord` 正常录音，却未被 PipeWire 检测到，可以尝试创建配置文件，手动添加该设备。

```
/etc/pipewire/pipewire.conf.d/microphone.conf (or ~/.config/pipewire/pipewire.conf.d/microphone.conf)
```

```
context.objects = [
    { factory = adapter
        args = {
            factory.name           = api.alsa.pcm.source
            node.name              = "microphone"
            node.description       = "未检测到的麦克风"
            media.class            = "Audio/Source"
            api.alsa.path          = "hw:card_number,device_number"
        }
    }
]
```

然后重启 PipeWire 以重新加载配置。

## 音频质量

### 节能机制导致爆音

[HECI](https://en.wikipedia.org/wiki/HECI) 控制器受到电源管理影响时可能导致爆音。可以通过 [powertop](../../02_系统管理与内核/电源管理/Powertop.md) 禁用运行时电源管理（Runtime PM）。

### 音频失真

- 对于麦克风，在运行 `alsamixer` 后找到存在问题的声卡，并使用方向键降低“Mic Boost”或“Internal Mic Boost”等麦克风增益选项。
- 参照[#更改默认采样率](#更改默认采样率)，将采样率降低至 `44100`（44.1 kHz）。

### 更改默认采样率

PipeWire 默认使用固定的 48 kHz 全局采样率。如需更改，可以设置新的默认值（但不推荐）：

```
/etc/pipewire/pipewire.conf.d/sample-rate.conf (or ~/.config/pipewire/pipewire.conf.d/sample-rate.conf)
```

```
context.properties = {
    default.clock.rate = sample_rate
}
```

不过，不建议这样做，因为这会影响延迟，而 quantum 的数值不会自动重新计算。如果希望保持相同的时间比例，则必须自行调整。引用官方文档的说明：

: *默认时钟采样率决定了最小、最大和默认 quantum 所对应的实时持续时间。更改默认时钟采样率时，你可能需要同时更改 quantum，以保持它们原来的持续时间。*

请注意，各音频流自身的采样率不会改变。PipeWire 只会进行重采样，以满足新的输出采样率。因此，原本无需处理的 48 kHz 音频流现在也会被重新采样。

如果设备支持多种采样率，建议保留默认设置，改为按照[#更改允许的采样率](#更改允许的采样率)进行配置。

### 更改允许的采样率

PipeWire 也可以根据 DAC 所支持的采样率动态改变输出采样率，使其跟随正在播放的音频流。例如：

```
/etc/pipewire/pipewire.conf.d/sample-rate.conf (or ~/.config/pipewire/pipewire.conf.d/sample-rate.conf)
```

```
context.properties = {
    default.clock.allowed-rates = [ 44100 48000 88200 96000 176400 192000 352800 384000 ]
}
```

假设默认采样率为 `48000`（即默认设置）。通常，如果音频流以 44100 Hz 输出（例如播放 CD 音质歌曲），PipeWire 会把它重采样到 48 kHz。但是，如果允许列表中包含 `44100`，PipeWire 则会检查音频流的 `44100` 是否在允许列表内，以及接收音频的输出设备（例如 DAC）是否支持该采样率。**如果都满足，DAC 就能在不进行重采样的情况下播放歌曲。**如果采样率不在列表中，或者 DAC 不支持它，PipeWire 就会退回默认采样率并进行重采样。

根据[开发者的说法](https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/1523)：“PipeWire 最多允许配置 16 种不同采样率，并会在可能时切换。”这意味着上述配置在设备支持时**不会进行重采样**。自 PipeWire [0.3.61](https://gitlab.freedesktop.org/pipewire/pipewire/-/releases/0.3.61#pipewire) 起，最多可配置 32 种采样率。

### 获取允许的采样率

查阅硬件手册，确认 DAC 支持的采样率。内核驱动编解码器报告的支持采样率可以通过以下命令查看：

```
$ grep -E 'Codec|Audio Output|rates' /proc/asound/card*/codec#*
```

如果 DAC 不报告编解码器信息，可以尝试通过以下命令获取支持的采样率：

```
$ grep -m1 -Hn "" /proc/asound/card?/stream? | tee /dev/tty | awk -F':' '{print $1}' | xargs grep 'Rates'
```

> **注意：**虽然 DAC 芯片可能报告高于产品标称规格的采样率，但其中一些仅用于 USB 转 I2S 等特殊模式。

### 检查当前使用的采样率

运行以下命令，检查某张声卡当前使用的输出采样率：

```
$ grep rate: /proc/asound/card?/pcm??/sub?/hw_params
```

```
/proc/asound/card1/pcm0p/sub0/hw_params:rate: 96000 (96000/1)
```

在 `pcm0p` 或 `pcm0c` 中，`c` 表示“capture”（采集），`p` 表示“playback”（播放）。

命令：

```
$ pw-top
```

也会显示各声卡和音频流当前使用的采样率。

> **提示：**如果在设置 default.clock.allowed-rates 后，DAC 仍不能切换到更高采样率，可能是系统无法读取 DAC 支持的采样率。这时仍可尝试设置 default.clock.rate。

## 硬件和声卡

### JBL Quantum 350 Wireless 与 Discord 的兼容问题

症状：当 Discord 发起音频输出或初始化音频配置时，没有声音；如果已经有其他声音正在播放，Discord 音频便可正常工作。例如会出现以下错误：

```
spa.alsa: front:0p: (125 suppressed) snd_pcm_avail after recover: Broken pipe
```

该错误会出现在 [系统日志](../../02_系统管理与内核/日志/Systemd_Journal.md)中。

至少有两种可能的解决方案：提高 `api.alsa.headroom`（例如设为 512），或设置合适的 `api.alsa.start-delay`。以下是针对 JBL Quantum 350 无线设备的示例：

```
~/.config/wireplumber/wireplumber.conf.d/52-jbl-quantum-350-discord-fix.conf
```

```
monitor.alsa.rules = [
   {
     matches = [
       {
         node.name = "alsa_output.usb-JBL_JBL_Quantum350_Wireless-00.analog-stereo"
       }
     ]
     actions = {
       update-props = {
         api.alsa.start-delay = 500
       }
     }
   }
 ]
```

然后在计算机上重启 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

### XiiSound / HAVIT Fuxi-H3 (040b:0897)

这款 USB 耳机在 PipeWire 和 WirePlumber 下有几个特殊问题：

- 仅在音量为 100% 时有声音——硬件音量范围过窄（0.00 dB 至 0.39 dB），使得 PipeWire 的分贝映射将较低音量全部转换为静音。
- 左声道静音——设备具有一个供左声道使用的次级 ALSA 混音器控制项（`PCM,1`，numid=10），WirePlumber 未初始化它，导致音量停留在 0%。
- 麦克风初始化时被静音——PipeWire 可能在启用静音的状态下创建采集源。

**修复方法 1——强制使用软件混音器：**

创建：

```
~/.config/wireplumber/wireplumber.conf.d/51-fuxi-h3-fix.conf
```

```
monitor.alsa.rules = [
   {
     matches = [
       {
         device.name = "alsa_card.usb-XiiSound_Technology_Corporation_Fuxi-H3-00"
       }
     ]
     actions = {
       update-props = {
         api.alsa.soft-mixer = true
         api.alsa.ignore-dB = true
         api.alsa.split-enable = false
       }
     }
   }
 ]
```

然后在计算机上重启 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

**修复方法 2——恢复左声道：**

```
$ amixer -c 0 cset numid=10 100
```

**修复方法 3——取消麦克风静音：**

```
$ pactl set-source-mute alsa_input.usb-XiiSound_Technology_Corporation_Fuxi-H3-00.mono-fallback 0
```

**使设置在重启后仍然有效：**

```
# alsactl store 0
```

### KDE Plasma 中未显示任何音频设备

PipeWire 客户端（包括桌面环境）可能依赖 [XDG_RUNTIME_DIR](https://specifications.freedesktop.org/basedir-spec/latest/#variables) [环境变量](../../02_系统管理与内核/系统管理/环境变量.md)来连接 PipeWire 守护进程。 如果登录后没有出现音频设备，原因可能是该变量被手动设置成了错误的路径。

尽管手动重启 PipeWire 可能暂时解决问题，但仍可能出现其他故障，例如无法在 Chromium 中共享屏幕（提示 `pipewire context failed`）。`XDG_RUNTIME_DIR` 会由 [pam_systemd(8)](https://man.archlinux.org/man/pam_systemd.8) 自动设置，因此应删除初始化文件中对它的所有手动赋值。

### 向 RAOP 设备（Sonos 等）串流时没有声音

使用 [Avahi](../../03_网络与服务/多播DNS/Avahi.md) 或 [systemd-resolved](../../03_网络与服务/网络/Systemd-resolved.md) 配置 mDNS 主机名解析。

### 从挂起状态恢复后实时优先级丢失／负载下爆音

> [![](https://wiki.archlinuxcn.org/wzh/images/6/62/Tango-edit-cut.png)](https://wiki.archlinuxcn.org/wzh/File:Tango-edit-cut.png)**这一章节正在考虑移除。**
>
> **原因:** 所述缺陷已于 2023 年迁移到 [新的 freedesktop.org 仓库](https://gitlab.freedesktop.org/pipewire/rtkit/-/merge_requests/35)后得到修复。 (在 [Talk:PipeWire/故障排除](https://wiki.archlinuxcn.org/wiki/Talk:PipeWire/%E6%95%85%E9%9A%9C%E6%8E%92%E9%99%A4) 讨论)

由于 rtkit 中一项[2011 年报告的缺陷](https://github.com/heftig/rtkit/issues/13)，系统挂起会导致 PipeWire 的实时优先级被撤销，且恢复运行后无法重新获得。若要关闭触发此问题的保护机制，请编辑 `rtkit-daemon.service`：

```
/etc/systemd/system/rtkit-daemon.service.d/override.conf
```

```
[Service]
ExecStart=
ExecStart=/usr/lib/rtkit-daemon --no-canary
```

然后重启 `rtkit-daemon.service` 系统单元、`pipewire.service` 用户单元及媒体会话服务。

### 同一声卡同时向多个音频输出设备输出

复制 `/usr/share/alsa-card-profile/mixer/profile-sets/default.conf`，以便更新后仍保留自定义更改。这里定义一个将模拟输出与 HDMI 的两个默认映射合并起来的配置文件。

```
/usr/share/alsa-card-profile/mixer/profile-sets/multiple.conf
```

```
[General]
auto-profiles = no

[Mapping analog-stereo]
device-strings = front:%f
channel-map = left,right
paths-output = analog-output analog-output-lineout analog-output-speaker analog-output-headphones analog-output-headphones-2
paths-input = analog-input-front-mic analog-input-rear-mic analog-input-internal-mic analog-input-dock-mic analog-input analog-input-mic analog-input-linein analog-input-aux analog-input-video analog-input-tvtuner analog-input-fm analog-input-mic-line analog-input-headphone-mic analog-input-headset-mic
priority = 15

[Mapping hdmi-stereo]
description = 数字立体声 (HDMI)
device-strings = hdmi:%f
paths-output = hdmi-output-0
channel-map = left,right
priority = 9
direction = output

[Profile multiple]
description = 模拟立体声双工 + 数字立体声 (HDMI) 输出
output-mappings = analog-stereo hdmi-stereo
input-mappings = analog-stereo
```

然后配置会话管理器，为匹配的设备使用新的声卡配置文件。可以通过 `pw-dump` 或 [wpctl](WirePlumber.md#Obtain_interface_name_for_rules_matching) 获取设备标识信息。

对于 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包：

```
/etc/wireplumber/wireplumber.conf.d/alsa-custom.conf (or ~/.config/wireplumber/wireplumber.conf.d/alsa-custom.conf)
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        device.nick = "HDA Intel PCH"
      }
    ]
    actions = {
      update-props = {
        api.alsa.use-acp = true
        api.acp.auto-profile = false
        api.acp.auto-port = false
        device.profile-set = "multiple.conf"
        device.profile = "multiple"
      }
    }
  }
]
```

对于 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包：

```
/etc/pipewire/media-session.d/alsa-monitor.conf (or ~/.config/pipewire/media-session.d/alsa-monitor.conf)
```

```
rules = [
    {
        matches = [ { alsa.card_name = "HDA Intel PCH" } ]
        actions = {
            update-props = {
                api.alsa.use-acp = true
                device.profile-set = "multiple.conf"
                device.profile = "multiple"
                api.acp.auto-profile = false
                api.acp.auto-port = false
            }
        }
    }
]
```

### USB DAC 的高延迟问题（例如 Schiit DAC）

更改采样率或音频格式可能有助于降低 Schiit Hel 2 等 DAC 的延迟。

对于 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包：

将默认配置文件 `/usr/share/pipewire/media-session.d/alsa-monitor.conf` 复制到 `/etc/pipewire/media-session.d/`（或 `~/.config/pipewire/media-session.d/`）。 然后添加类似下面的规则块：

```
/etc/pipewire/media-session.d/alsa-monitor.conf (or ~/.config/pipewire/media-session.d/alsa-monitor.conf)
```

```
...
rules = {
    ...
    {
        matches = [
            {
                node.name = "alsa_output.name-of-node"
            }
        ]
        actions = {
            update-props = {
                audio.format = "S24_3LE"
                audio.rate = 96000
                # 如果声音仍有中断或其他问题，请逐次将以下数值加倍
                api.alsa.period-size = 128
...
```

对于 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包：

```
/etc/wireplumber/wireplumber.conf.d/update-rate-and-format.conf (or ~/.config/wireplumber/wireplumber.conf.d/update-rate-and-format.conf)
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        node.name = "alsa_output.name-of-node"
      }
    ]
    actions = {
      update-props = {
        audio.format = "S24_3LE"
        audio.rate = 96000
        # 如果声音仍有中断或其他问题，请逐次将以下数值加倍
        api.alsa.period-size = 128
      }
    }
  }
]
```

可以用 `pw-top` 获取 `alsa_output.*name-of-node*` 节点名称。

你的 DAC 可能支持不同的格式或采样率。可以通过查询 [ALSA](../../04_硬件与外设/声音/ALSA.md) 来检查 DAC 所支持的参数：

首先获取 DAC 的声卡编号：

```
$ aplay -l
```

```
...
card 3: S2 [Schiit Hel 2], device 0: USB Audio [USB Audio]
  Subdevices: 0/1
  Subdevice #0: subdevice #0
...
```

因此，本例中的声卡编号为 3。 获取所有受支持的采样率及格式：

```
$ cat /proc/asound/cardX/streamX
```

```
...
Playback:
  ...
  Interface 1
    Altset 1
    Format: S16_LE
    Channels: 2
    Endpoint: 0x05 (5 OUT) (ASYNC)
    Rates: 44100, 48000, 88200, 96000, 176400, 192000, 352800, 384000
    Data packet interval: 125 us
    Bits: 16
    ...
  Interface 1
    Altset 2
    Format: S24_3LE
    Channels: 2
    Endpoint: 0x05 (5 OUT) (ASYNC)
    Rates: 44100, 48000, 88200, 96000, 176400, 192000, 352800, 384000
    Data packet interval: 125 us
    Bits: 24
    ...
  Interface 1
    Altset 3
    Format: S32_LE
    Channels: 2
    Endpoint: 0x05 (5 OUT) (ASYNC)
    Rates: 44100, 48000, 88200, 96000, 176400, 192000, 352800, 384000
    Data packet interval: 125 us
    Bits: 32
    ...
...
```

本例中，支持的格式为 `S16_LE, S24_3LE, S32_LE`；所有格式合计支持的采样率为 `44100, 48000, 88200, 96000, 176400, 192000, 352800, 384000`。

### USB DAC 音量达到 30% 后才有声音

某些 USB DAC 只有在音量达到一定数值后才能输出声音。通常阈值在 15% 至 30% 左右，这可能导致初始音量过大，并且无法维持低音量。解决方法是将该设备的 `api.alsa.soft-mixer` 设为 `true`，忽略硬件混音器的音量控制。

在 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包 中可以使用以下配置：

```
/etc/wireplumber/wireplumber.conf.d/alsa-soft-mixer.conf (or ~/.config/wireplumber/wireplumber.conf.d/alsa-soft-mixer.conf)
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        device.name = "alsa_card.name-of-device"
      }
    ]
    actions = {
      update-props = {
        # 不使用硬件混音器控制音量，仅通过软件调节音量。
        # 但仍使用混音器，根据所选端口
        # 将未使用的音频通路静音。
        api.alsa.soft-mixer = true
      }
    }
  }
]
```

参见 [获取用于规则匹配的接口名称](WirePlumber.md#Obtain_interface_name_for_rules_matching)，以确定替换 `"alsa_card.*name-of-device*"` 所需的正确值。

也可以指定 `"~alsa_card.*"`，将规则应用到所有音频设备。

然后重启 PipeWire，例如运行 `systemctl --user restart pipewire`。在 `alsamixer` 中设置主音量，然后以 root 身份执行 `alsactl store` 保存设置。现在应该可以正常使用音量控制器了。

### 实时音频无法工作

如果 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)的[状态](https://wiki.archlinuxcn.org/wzh/Help:%E9%98%85%E8%AF%BB#控制_systemd_单元)中出现 `RTKit error: org.freedesktop.DBus.Error.AccessDenied`，说明 PipeWire 守护进程未能获得实时优先级。参见[此问题报告](https://gitlab.freedesktop.org/pipewire/pipewire/-/issues/1069)。

### 外接声卡重新连接后未激活

检查 `~/.config/pipewire/media-session.d/default-profile` 中是否存在默认配置文件为 "off" 的条目，如有则将其删除。如果仍无法解决，删除 `~/.config/pipewire/media-session.d/` 内的所有文件并重启 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

### 没有声音，或 pactl info 显示 Failure: Connection refused

这意味着应用程序无法连接到 PipeWire-Pulse 服务。请检查 `pipewire-pulse.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)是否正在运行。

如果无法解决问题，请运行 `strace -f -o /tmp/pipe.txt pactl info`，并将 `/tmp/pipe.txt` 上传到 pastebin，以便在 IRC（OFTC 上的 #pipewire）或邮件列表上寻求帮助。

### 连接新设备时声音未自动切换

若要自动切换到新连接的设备，请创建以下文件：

```
/etc/pipewire/pipewire-pulse.conf.d/switch-on-connect.conf (or ~/.config/pipewire/pipewire-pulse.conf.d/switch-on-connect.conf)
```

```
pulse.cmd = [
    { cmd = "load-module" args = "module-switch-on-connect" }
]
```

然后使用 [systemctl --user](../../02_系统管理与内核/系统管理/Systemd_用户.md) 重启 `pipewire-pulse.service`，并检查 `module-switch-on-connect` 是否已加载。

### 连接蓝牙设备后没有声音

截至 2020 年 12 月 7 日，如果连接蓝牙设备后没有声音，可能需要切换默认输出设备，或将音频流输入移动到正确的输出设备。使用 `pactl list sinks` 列出可用输出设备，再使用 `pactl set-default-sink` 将默认输出切换到蓝牙设备。也可以借助 [udev](../../04_硬件与外设/硬件检测和故障排除/Udev.md)，使用类似[这个脚本](https://gist.github.com/tinywrkb/04e7fd644afa9b92d33a3a99ab07ee9e)的方式自动完成。

参见[此 Reddit 讨论](https://www.reddit.com/r/archlinux/comments/jydd02/pipewirepulse_03164_in_testing_now_replaces/gd3m7fu/?context=3)。根据脚本作者的说法，耳机配置文件（HSP）仍可能存在问题。

## 蓝牙

### 蓝牙音频质量低

如果蓝牙播放出现卡顿，请检查 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)的[状态](https://wiki.archlinuxcn.org/wzh/Help:%E9%98%85%E8%AF%BB#控制_systemd_单元)，寻找类似以下内容的错误：

```
Feb 17 18:23:01 HOST pipewire: (bluez_input.18:54:CF:04:00:56.a2dp-sink-60) client too slow! rate:512/48000 pos:370688 status:triggered
```

如果出现这些错误，请使用 `pactl list sinks` 检查当前选择的编解码器，并尝试将 `bluez5.codec` 设置为 `sbc aac ldac aptx aptx_hd` 中的一种。还可以尝试 mSBC 支持（可修复 Sony 1000XM3，即 WH-1000XM3 耳机和 WF-1000XM3 真无线耳机的麦克风问题），以及 SBC-XQ 编解码器。

> **注意：**对于 WH-1000XM3 等耳机，如果在配套应用中将“声音质量模式”设置为“优先稳定连接”而不是“优先音质”，耳机就不会公布 SBC/SBC-XQ 以外的其他编解码器。

对于 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包：

```
/etc/wireplumber/wireplumber.conf.d/bluez-config.conf (or ~/.config/wireplumber/wireplumber.conf.d/bluez-config.conf)
```

```
monitor.bluez.properties = {
  bluez5.enable-sbc-xq = true
  bluez5.enable-msbc = true
  bluez5.codecs = [ sbc sbc_xq ]
}
```

对于 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包：

```
/etc/pipewire/media-session.d/bluez-monitor.conf (or ~/.config/pipewire/media-session.d/bluez-monitor.conf)
```

```
...
properties = {
  ...
  bluez5.enable-msbc = true
  bluez5.enable-sbc-xq = true
  bluez5.codecs = [sbc sbc_xq]
...
```

通过重启 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)来重启 PipeWire，使更改生效。

## 应用程序

### 终端提示铃不响

从 PipeWire 的角度来看，必须加载 x11.bell 模块。该模块本应在配置中默认启用（也可以检查前面提到的配置文件）。检查是否安装了 [pipewire-x11-bell](https://archlinux.org/packages/?name=pipewire-x11-bell)包 软件包。窗口管理器也可能影响终端提示铃，例如在 xfwm 中需要检查 xfwm-terminal 的设置，确保已启用“Audible bell”（可听提示铃）。然后重启 PipeWire 服务：

```
$ systemctl --user restart pipewire
```

可以运行以下命令测试终端提示铃是否正常：

```
$ echo $'\a'
```

### OBS 等应用无法显示画面，即使已经请求选择窗口或屏幕

如果确信已安装 [xdg-desktop-portal](https://archlinux.org/packages/?name=xdg-desktop-portal)包 以及 [xdg-desktop-portal-gtk](https://archlinux.org/packages/?name=xdg-desktop-portal-gtk)包 或 [xdg-desktop-portal-kde](https://archlinux.org/packages/?name=xdg-desktop-portal-kde)包，请检查相关守护进程是否正在运行。

如果 OBS 正常工作，应该在 `stdout` 中看到以下内容：

```
...
info: [pipewire] desktop selected, setting up screencast
info: [pipewire] created stream 0x5632d7456850
info: [pipewire] playing stream…
```

对于多显示器设置，[slurp](https://archlinux.org/packages/?name=slurp)包 软件包可以帮助捕获所有屏幕。

### 使用 FMOD 的游戏在 PipeWire 下崩溃

一些使用旧版本 [FMOD 音频引擎](https://en.wikipedia.org/wiki/FMOD)的游戏（例如 [永恒之柱](https://en.wikipedia.org/wiki/Pillars_of_Eternity)）会调用 `pulseaudio --check`，并在缺少 PulseAudio 可执行文件时崩溃。一种规避方法是创建从 `/bin/pulseaudio` 指向 `/bin/true` 的符号链接。

```
# ln -s /bin/true /bin/pulseaudio
```

请注意，如果以后要重新安装 PulseAudio，需要先删除该符号链接。

### Discord 没有通知声音

这可能是由于 min.quantum 太低；可以尝试将其设置为大于 700 的值。可在 pipewire-pulse.conf 的 pulse.rules 部分添加如下规则，仅覆盖 Discord 的相关设置。

```
/etc/pipewire/pipewire-pulse.conf (or ~/.config/pipewire/pipewire-pulse.conf)
```

```
...
pulse.rules = [
  ...
    {
        # 修复 Discord 通知声音
        matches = [ { application.process.binary = "Discord" } ]
        actions = {
            update-props = {
                pulse.min.quantum      = 1024/48000     # 21ms
            }
        }
    }
...
```

### 多个音频流开始播放时声音中断

通常可以通过查看 `pipewire-pulse.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)的[日志](../../02_系统管理与内核/日志/Systemd_Journal.md)来诊断此问题，其中可能出现类似以下的记录：

```
pipewire-pulse: pulse-server 0x56009b9d5de0: [Nightly] UNDERFLOW channel:0 offset:370676 underrun:940
```

根据 [PipeWire 官方故障排除指南](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Troubleshooting#underrununderflow-and-broken-pipe-errors)，对于 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包，可使用以下配置解决：

```
/etc/wireplumber/wireplumber.conf.d/alsa-config.conf (or ~/.config/wireplumber/wireplumber.conf.d/alsa-config.conf)
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        node.name = "~alsa_output.*"
      }
    ]
    actions = {
      update-props = {
        api.alsa.period-size   = 1024
        api.alsa.headroom      = 8192
      }
    }
  }
]
```

对于 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包：

```
/etc/pipewire/media-session.d/alsa-monitor.conf (or ~/.config/pipewire/media-session.d/alsa-monitor.conf
```

```
api.alsa.headroom = 1024
```

如果音频卡顿是由内核页面锁定或调度不及时造成的，请参见 [游戏#调整内核参数以实现响应时间一致性](../游戏/游戏.md#调整内核参数以实现响应时间一致性)。

## 其他问题

### 自动切换功能无法工作

如果自动切换无法正常工作，问题可能出在 [WirePlumber](WirePlumber.md) 的状态数据上。按照[此评论](https://gitlab.freedesktop.org/pipewire/wireplumber/-/issues/191#note_1252549)的建议，可以删除 [WirePlumber](WirePlumber.md) 的本地状态并重启守护进程，查看是否有所改善：

```
$ rm -r ~/.local/state/wireplumber/
```

然后重启 `wireplumber.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

### 待机恢复后出现音频问题

如果计算机从睡眠中唤醒后没有声音，或声音异常失真，可能是声卡未能正确恢复。临时解决方法是重启 PipeWire 和 WirePlumber：

```
# systemctl --user restart pipewire pipewire-pulse wireplumber
```

### 增加 RLIMIT_MEMLOCK

```
Dec 13 11:11:11 HOST pipewire-pulse: Failed to mlock memory 0x7f4f659d8000 32832: This is not a problem but for best performance, consider increasing RLIMIT_MEMLOCK
```

安装 [realtime-privileges](https://archlinux.org/packages/?name=realtime-privileges)包，并将当前用户加入 `realtime` 用户组。

另一种方法是将 memlock 限制从 64 kB 提升到 128 kB，这似乎足以修复问题。如果通过 [systemd/用户](../../02_系统管理与内核/系统管理/Systemd_用户.md) 运行 `pipewire-pulse`，请添加：

```
username	soft	memlock	64
username	hard	memlock	128
```

将这些内容写入 `/etc/security/limits.d/username.conf`。

### 开始播放时出现明显延迟或可听见的爆音

这是因为节点在空闲时被挂起。

对于 [wireplumber](https://archlinux.org/packages/?name=wireplumber)包，创建一个新的配置文件覆盖默认设置：

```
/etc/wireplumber/wireplumber.conf.d/disable-suspension.conf (or ~/.config/wireplumber/wireplumber.conf.d/disable-suspension.conf)
```

```
monitor.alsa.rules = [
  {
    matches = [
      {
        # 匹配所有输入源
        node.name = "~alsa_input.*"
      },
      {
        # 匹配所有输出设备
        node.name = "~alsa_output.*"
      }
    ]
    actions = {
      update-props = {
        session.suspend-timeout-seconds = 0
      }
    }
  }
]
# 蓝牙设备
monitor.bluez.rules = [
  {
    matches = [
      {
        # 匹配所有输入源
        node.name = "~bluez_input.*"
      },
      {
        # 匹配所有输出设备
        node.name = "~bluez_output.*"
      }
    ]
    actions = {
      update-props = {
        session.suspend-timeout-seconds = 0
      }
    }
  }
]
```

重启 `pipewire.service` 和 `wireplumber.service` 使更改生效。

除了完全禁用挂起，也可以更改超时值，指定音频源在多少秒无活动后才挂起。

某些设备自行检测静音并进入休眠。对于这些设备，仅禁用节点挂起仍无效。可以通过添加少量噪声来规避静音检测，使输出始终不会完全静音：

```
.../disable-suspension.conf
```

```
...
    session.suspend-timeout-seconds = 0,  # 0 表示禁用挂起
    dither.method = "wannamaker3", # 添加指定形状的抖动噪声
    dither.noise = 2, # 增加额外的噪声位数
...
```

可能需要调整 `dither.noise` 和 `dither.method` 参数，使噪声既足够安静，又足以防止设备检测到静音。参见 [PipeWire 文档](https://docs.pipewire.org/page_man_pipewire-client_conf_5.html#client_conf__dither_noise)。

对于 [pipewire-media-session](https://archlinux.org/packages/?name=pipewire-media-session)包：

根据延迟发生的位置，编辑 `/etc/pipewire/media-session.d/*-monitor.conf`，将 `session.suspend-timeout-seconds` 属性改为 0 以禁用挂起，或者尝试其他数值，观察效果。

也可以在 `/etc/pipewire/media-session.d/media-session.conf` 中注释掉 `suspend-node` 这一行。

重启 `pipewire.service` 与 `pipewire-pulse.service` 以应用更改，或直接重启计算机。

### 首次尝试播放后才有声音

如果 PipeWire 通过套接字激活启动，部分原生 PipeWire 应用可能会在 [WirePlumber](WirePlumber.md) 完成节点配置之前就尝试播放音频，从而出现错误，例如：

```
$ mpv -v /path/to/file
```

```
[ao/pipewire] PipeWire does not have any audio sinks, skipping
[ao] Failed to initialize audio driver 'pipewire'
```

```
$ journalctl --user -u mpd.service
```

```
output: Failed to play on "PipeWire" (pipewire): no target node available
exception: Failed to open audio output
```

规避方法是启用 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

## 3.12　PipeWire

*难度：高级 ｜ 篇幅：38.7 KB ｜ 所属：多媒体*

将要讲到：安装、配置、用法、音频后期处理、参阅

[PipeWire](https://pipewire.org) 是一个新的底层多媒体框架。 它旨在以最低的延迟为音频和视频提供录制和播放功能，并支持基于 [PulseAudio](../../04_硬件与外设/声音/PulseAudio.md)、[JACK](../../04_硬件与外设/声音/JACK%20Audio%20Connection%20Kit.md)、[ALSA](../../04_硬件与外设/声音/ALSA.md) 和 [GStreamer](GStreamer.md) 的应用程序。

基于该框架的守护进程可以配置为音频服务器(具有 PulseAudio 和 JACK 特性)和视频录制服务器。

PipeWire 还支持像 [Flatpak](../../07_开发与工具/开发/Flatpak.md) 这样的容器，不依赖于 `audio` 和 `video` [用户组](../../08_安全与加密/安全/用户和用户组.md)。 相反，它采用了类似于 [Polkit](../../08_安全与加密/安全/Polkit.md)的安全模式，向 Flatpak 或 Wayland 请求许可以录制屏幕或音频。

## 用法

### 声音

PipeWire 可以用作音频服务器，类似于 PulseAudio 和 JACK，它旨在通过为JACK客户端提供PulseAudio兼容的服务器实现和ABI兼容库来取代PulseAudio和JACK。有关详细信息，请参阅博客文章[PipeWire Late Summer Update 2020](https://blogs.gnome.org/uraeus/2020/09/04/pipewire-late-summer-update-2020/)。

首先，安装 [pipewire-audio](https://archlinux.org/packages/?name=pipewire-audio)包。然后根据音频客户端的类型，可能还需要执行一些额外的步骤。您可能需要为您的音频设备安装额外的固件，请参阅[ALSA#固件](../../04_硬件与外设/声音/ALSA.md#固件)。

#### ALSA 客户端

安装 [pipewire-alsa](https://archlinux.org/packages/?name=pipewire-alsa)包 (如果安装了[pulseaudio-alsa](https://archlinux.org/packages/?name=pulseaudio-alsa)包需要删掉它) 以使用 ALSA API 通过 PipeWire 路由所有应用程序。

#### PulseAudio 客户端

安装 [pipewire-pulse](https://archlinux.org/packages/?name=pipewire-pulse)包。它将代替 [pulseaudio](https://archlinux.org/packages/?name=pulseaudio)包 和 [pulseaudio-bluetooth](https://archlinux.org/packages/?name=pulseaudio-bluetooth)包。重新启动、重新登录或 start `pipewire-pulse.service` [user unit](../../02_系统管理与内核/系统管理/Systemd_用户.md) 以查看效果。

通常，不需要进一步的操作，应用应作为用户服务自动启用`pipewire-pulse.socket`。要检查替换是否正常工作，请运行以下命令并查看输出：

```
$ pactl info
```

```
...
Server Name: PulseAudio (on PipeWire x.y.z)
...
Default Sink: alsa_output.{bus}device}.{profile}
Default Source: alsa_input.{bus{device}.{profile}
...
```

[pactl(1)](https://man.archlinux.org/man/pactl.1) 命令由 PulseAudio 客户端库（[libpulse](https://archlinux.org/packages/?name=libpulse)包）提供，该库会作为依赖项随 *pipewire-pulse* 自动安装。

##### 调节全局或独立声道音量

调节输出声道音量时，需通过 `pactl get-sink-volume {sink`} 指定目标设备，可使用： - 上文 *Default Sink:* 或下文 *Name:* 的值 - 默认设备占位符 *@DEFAULT_SINK@* - 设备编号 *Sink #*（如下例中的 *1*）

```
$ pactl list sinks | grep -B1 -A9 State:
```

```
Sink #1
        State: RUNNING
        Name: alsa_output.pci-0000_2d_00.4.analog-surround-51
...
        Driver: PipeWire
...
        Mute: no
        Volume: front-left: 65536 / 100% / 0.00 dB,   front-right: 65536 / 100% / 0.00 dB,   rear-left: 65536 / 100% / 0.00 dB,   rear-right: 65536 / 100% / 0.00 dB,   front-center: 65536 / 100% / 0.00 dB,   lfe: 65536 / 100% / 0.00 dB
                balance 0.00
```

提示：若当前有音频播放，可通过 [grep(1)](https://man.archlinux.org/man/grep.1) 筛选 *RUNNING*（运行中）状态设备，其他设备通常显示为 *SUSPENDED*（已挂起）。

*balance*（声道平衡）数值会自动计算。设置默认设备的整体音量：

```
pactl set-sink-volume @DEFAULT_SINK@ 75%
```

独立设置各声道音量（需提供每个声道的百分比）：

```
pactl set-sink-volume @DEFAULT_SINK@ 100% 75% 100% 75% 100% 100%
```

*Source*（输入设备）的操作方式类似。更多配置（如模块加载）请参考上游维基： [Migration from PulseAudio](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Migrate-PulseAudio) [Pipewire-Pulse Configuration](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Config-PulseAudio).

#### JACK 客户端

安装 [pipewire-jack](https://archlinux.org/packages/?name=pipewire-jack)包 以获取 [JACK](../../04_硬件与外设/声音/JACK%20Audio%20Connection%20Kit.md) 支持。还有 [lib32-pipewire-jack](https://archlinux.org/packages/?name=lib32-pipewire-jack)包 用于 [multilib](../../00_关于与社区/关于%20Arch/官方仓库.md) 支持。

[pw-jack(1)](https://man.archlinux.org/man/pw-jack.1) 可以用来启动 JACK 客户端， 但从技术上讲它不是必需的， 因为它只用作 `PIPEWIRE_REMOTE`、`PIPEWIRE_DEBUG` 和 `PIPEWIRE_LATENCY` 环境变量的包装器。

可以通过设置 缓冲区大小/采样率 的商（等于以秒为单位的块延迟）来请求自定义缓冲区大小：

```
PIPEWIRE_LATENCY="128/48000" application
```

#### 蓝牙设备

如果安装了 [pipewire-pulse](https://archlinux.org/packages/?name=pipewire-pulse)包 软件包，PipeWire 将自动处理[蓝牙音频设备](../../04_硬件与外设/蓝牙/蓝牙.md#音频)。

        ...

            update-props = {
                ...

#### 用于命令行的 PipeWire 补丁集

[qpwgraph](https://archlinux.org/packages/?name=qpwgraph)包 可用于可视化和创建连接，以及保存和加载补丁集。 对于非 GUI 需求，以下是用于保存线集、加载线集和解除所有连接的 bash 脚本。 要保存和加载，请使用命令行参数作为文件名。

#!/bin/bash

if [[ "$#" -ne 1 ]]; then
	echo
	echo 'usage: pw-savewires filename'
	echo
	exit 0
fi

rm $1 &> /dev/null
while IFS= read -r line; do
	link_on=`echo $line | cut -f 4 -d '"'`
	link_op=`echo $line | cut -f 6 -d '"'`
	link_in=`echo $line | cut -f 8 -d '"'`
	link_ip=`echo $line | cut -f 10 -d '"'`
	echo "Saving: " "'"$link_on:$link_op"','"$link_in:$link_ip"'"
	echo "'"$link_on:$link_op"','"$link_in:$link_ip"'" >> $1
done < <(pw-cli dump short link)
```

#### 与网络上的计算机共享音频设备

PipeWire 支持使用多种机制通过网络共享音频，包括：

- [AES67](https://en.wikipedia.org/wiki/AES67)
- [RTP](https://en.wikipedia.org/wiki/Real-time_Transport_Protocol)
- [Apple Airplay](https://en.wikipedia.org/wiki/AirPlay) (without DRM features)
- JACK ([netjack2](https://github.com/jackaudio/jack2/blob/develop/README_NETJACK2))
- [Roc](https://roc-streaming.org/)
- [PipeWire Native RTP](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Guide-Network-RTP)
- [PulseAudio's network protocol](https://docs.pipewire.org/page_module_pulse_tunnel.html)
- [Snapcast](https://github.com/badaix/snapcast)

PipeWire维基上有一个[页面](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Network)，概述并比较了不同的网络协议。

下文将介绍 Pulse Tunnel（Pulse 音频隧道） 方案。PipeWire 的 PulseAudio 兼容层支持 [网络音频串流](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Config-PulseAudio#network-support)。在网络上的计算机之间共享音频的一种简单方法是使用 Avahi 守护程序进行发现。要启用此功能，请安装 pipewire-zeroconf包 软件包。

确保所有要共享声音的计算机上的 `avahi-daemon.service` 正在运行（如果使用 [firewall](../../03_网络与服务/多播DNS/Avahi.md#Firewall)，则要保证 UDP 端口 `5353` 已打开）。

> **注意：**某些 GUI 卷管理器默认隐藏网卡。（例如：在 Plasma 中，必须“配置音频音量...”并选中“显示虚拟设备”。

要共享本地音频设备，在主机上加载适当的模块（确保使用本地 IP 地址）：

```
$ pactl load-module module-native-protocol-tcp listen=192.168.1.10
$ pactl load-module module-zeroconf-publish
```

然后在客户端上加载发现模块：

```
$ pactl load-module module-zeroconf-discover
```

还可以通过创建专用配置文件自动加载模块。

主机：

```
/etc/pipewire/pipewire-pulse.conf.d/50-zeroconf-publish.conf (or ~/.config/pipewire/pipewire-pulse.conf.d/50-zeroconf-publish.conf)
```

```
pulse.cmd = [
    { cmd = "load-module" args = "module-native-protocol-tcp listen=192.168.1.10" }
    { cmd = "load-module" args = "module-zeroconf-publish" }
]
```

客户端:

```
/etc/pipewire/pipewire-pulse.conf.d/50-zeroconf-discover.conf (or ~/.config/pipewire/pipewire-pulse.conf.d/50-zeroconf-discover.conf)
```

```
pulse.cmd = [
    { cmd = "load-module" args = "module-zeroconf-discover" }
]
```

##### 将音频串流到 AirPlay 接收器

可以将音频串流到冒充 [AirPlay 接收器](https://en.wikipedia.org/wiki/AirPlay#Receivers)的设备。 要启用此功能，请加载 [RAOP Discover 模块](https://docs.pipewire.org/page_module_raop_discover.html)：

```
$ pactl load-module module-raop-discover
```

还可以通过创建专用配置文件自动加载此模块：

```
/etc/pipewire/pipewire.conf.d/raop-discover.conf (or ~/.config/pipewire/pipewire.conf.d/raop-discover.conf)
```

```
context.modules = [
   {
       name = libpipewire-module-raop-discover
       args = { }
   }
]
```

某些扬声器的 AirPlay 实现（例如 Sonos AirPlay 2 扬声器）可能需要为源设备上的传入 UDP 流量打开端口 6001 和 6002。

##### 通过 Roc 实现设备间音频串流

[Roc streaming](https://roc-streaming.org/) 是一套支持前向纠错的实时音频网络传输协议。PipeWire 默认内置对它的支持，配置十分简便。 首先 安装 [pipewire-roc](https://archlinux.org/packages/?name=pipewire-roc)包 软件包。

接收端 / 主机 / DAC 配置：

```
~/.config/pipewire/pipewire.conf.d/
```

```
context.modules = [
  { name = libpipewire-module-roc-source
    args = {
        local.ip = 0.0.0.0
        roc.resampler.backend = default
        roc.resampler.profile = default
        roc.latency-tuner.backend = default
        roc.latency-tuner.profile = default
        fec.code = default
        sess.latency.msec = 100
        local.source.port = 10001
        local.repair.port = 10002
        local.control.port = 10003
    }
  }
]
```

更多参数可查阅 [PipeWire 官方文档](https://docs.pipewire.org/page_module_roc_source.html)。

> **注意：** 该方案在搭载新版树莓派系统的树莓派声卡（DAC）上运行效果极佳。

发送端 / 客户端配置：

```
~/.config/pipewire/pipewire.conf.d/roc-sink.conf
```

```
context.modules = [
  { name = libpipewire-module-roc-sink
    args = {
        fec.code = default
        remote.ip = <主机 IP 地址>
        remote.source.port = 10001
        remote.repair.port = 10002
        remote.control.port = 10003
        sink.props = {
            node.name = "my-roc-sink"
            node.description = "my-roc-sink"
        }
    }
  }
]
```

更多参数可查阅 [PipeWire 官方文档](https://docs.pipewire.org/page_module_roc_sink.html)。

> **注意：**`node.description` 用于设置 *pulsemixer* 显示的设备名称；`node.name` 供 *pactl* 工具读取。建议两项均进行配置。

在两台设备上 重启 `pipewire.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

#### 在本地 JACK 上运行 PipeWire

如果需要，PipeWire 也可以作为 JACK 客户端在本机 JACK 守护程序之上运行。

请参阅 [JACK 和 PipeWire (PipeWire wiki)](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/JACK) 和 [\-JACK#jack-bridge JACK 桥(PipeWire wiki)](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Config) 了解更多信息和附加配置（例如可用通道）。

要使用它，请安装 [pipewire-jack-client](https://archlinux.org/packages/?name=pipewire-jack-client)包 并启动 JACK。Pipewire 应该会被自动桥接。

> **注意：**自从 pipewire [0.3.81版本](https://gitlab.freedesktop.org/pipewire/pipewire/-/releases/0.3.81) 加载 jackdbus 模块是自动完成的，而且不再是必须的。
>
> 它可以在启动 jack 之前像 PulseAudio 模块一样手动加载（在[pactl(1)](https://man.archlinux.org/man/pactl.1)解释）：`pactl load-module module-jackdbus-detect`。

#### 使用 ALSA dmix 设备作为 PipeWire 接收器

可以通过 [ALSA dmix devices](../../04_硬件与外设/声音/ALSA.md#Dmix) 将 PipeWire 服务器（或每个用户多个）输出到 ALSA。这允许您使用 ALSA 作为主要音频输出系统，同时能够使用非 ALSA 设备，例如蓝牙耳机。

##### ALSA dmix 设置

假设您有两张卡：`PCH` 和 `HDMI`：

```
/proc/asound/cards
```

```
 0 [PCH            ]: HDA-Intel - HDA Intel PCH
                      HDA Intel PCH at 0xdff40000 irq 146
 1 [HDMI           ]: HDA-Intel - HDA ATI HDMI
                      HDA ATI HDMI at 0xdfe60000 irq 147
```

你的 PCM 看起来长这样：

```
/proc/asound/pcm
```

```
00-00: ALC1220 Analog : ALC1220 Analog : playback 1 : capture 1
00-02: ALC1220 Alt Analog : ALC1220 Alt Analog : capture 1
01-03: HDMI 0 : HDMI 0 : playback 1
01-07: HDMI 1 : HDMI 1 : playback 1
01-08: HDMI 2 : HDMI 2 : playback 1
01-09: HDMI 3 : HDMI 3 : playback 1
01-10: HDMI 4 : HDMI 4 : playback 1
01-11: HDMI 5 : HDMI 5 : playback 1
```

假设您的 ALSA 配置如下所示：

```
/etc/asound.conf
```

```
ctl.!default {
  type hw
  card PCH
}

pcm.!default {
  type plug
  slave.pcm "dmix:PCH,0"
}

pcm.dhdmi {
  type plug
  slave.pcm "dmix:HDMI,9"
}
```

在此特定示例中，dmix 设备为 `dmix:PCH,0` 和 `dmix:HDMI,9`。

##### PipeWire dmix 设置

首先，通过禁用 `monitor.alsa` 来阻止 `wireplumber` 监控和添加硬件 ALSA 设备：

```
/etc/wireplumber/wireplumber.conf.d/disable-alsa-monitor.conf (or ~/.config/wireplumber/wireplumber.conf.d/disable-alsa-monitor.conf)
```

```
wireplumber.profiles = {
  main = {
    monitor.alsa = disabled
  }
}
```

现在，配置 `pipewire` 以使用 dmix 设备。 默认配置文件（`/usr/share/pipewire/pipewire.conf`）包含一个[注释掉了的示例](https://gitlab.freedesktop.org/pipewire/pipewire/-/blob/0.3.59/src/daemon/pipewire.conf.in#L219-239)，您可以将其用作模板。

将您自己的元素添加到 `context.objects` 数组中：

```
/etc/pipewire/pipewire.conf.d/alsa-dmix.conf (or ~/.config/pipewire/pipewire.conf.d/alsa-dmix.conf)
```

```
context.objects = [
    # We do not start with dmix, but with an input device.
    # Do not forget to add an input device.
    # On a friend's Laptop, I saw Zoom having a nervous
    # breakdown and endlessly crying because no input device
    # was configured! You have been warned.
    { factory = adapter
        args = {
            factory.name           = api.alsa.pcm.source
            node.name              = "alsa-mic-internal" # name of pulse device (mpv)
            node.description       = "Mic Internal" # name of pulse device (pavucontrol)
            media.class            = "Audio/Source"
            api.alsa.path          = "hw:PCH,0"
        }
    }
    # Okay, now we add our dmix PCMs
    { factory = adapter
        args = {
            factory.name           = api.alsa.pcm.sink # sink for dmix
            node.name              = "alsa-dmix-internal" # name of pulse device (mpv)
            node.description       = "PCM Internal" # name of pulse device (pavucontrol)
            media.class            = "Audio/Sink" # Sink for dmix
            api.alsa.path          = "dmix:PCH,0"
        }
    }

    { factory = adapter
        args = {
            factory.name           = api.alsa.pcm.sink # sink for dmix
            node.name              = "alsa-dmix-hdmi" # name of pulse device (mpv)
            node.description       = "PCM HDMI" # name of pulse device (pavucontrol)
            media.class            = "Audio/Sink" # Sink for dmix
            # remember this is a non-default dmix from /etc/asound.conf
            api.alsa.path          = "dmix:HDMI,9"
        }
    }
]
```

作为用户（非 root），检查 `wpctl status` 的输出，并使用`wpctl set-default *ID*`根据您的喜好设置默认输入（源）和输出（接收器）设备。`*ID*` 是接收器/源名称之前的数字。

现在，您可以全面测试您的配置。

#### 多用户音频共享

有时允许其他用户连接到当前用户的 PipeWire 实例会很实用。例如，你通过 [Xephyr](../../05_桌面与图形/X%20服务器/Xephyr.md) 登录另一个用户账户，希望 Xephyr 会话内播放的音频从外部用户管理的扬声器输出。

实现该需求的一种方式是配置外部用户的 pipewire-pulse，使其监听本地 TCP 连接。

在外部用户家目录下新建如下配置文件：

```
~/.config/pipewire/pipewire-pulse.conf.d/pulse-server.conf
```

```
pulse.properties = {
server.address = [
"unix:native"
"tcp:127.0.0.1:4713" # 此时外部用户的 pipewire 服务会监听 IPv4 本地回环地址
]
}
```

之后在内层用户会话中设置环境变量 `PULSE_SERVER=tcp:127.0.0.1:4713`。比如以内层用户身份启动 [Xephyr](../../05_桌面与图形/X%20服务器/Xephyr.md) 前执行导出该变量。更多说明与其他配置方案可参阅[该论坛帖子](https://bbs.archlinux.org/viewtopic.php?id=265878)

### WebRTC 屏幕共享

大多数应用程序过去依赖 X11 来捕获桌面（或单个应用程序），例如在网络浏览器中使用 WebRTC 时（例如在 Google Hangouts 上）。 在 Wayland 上，屏幕共享机制由 [XDG Desktop Portal](../../05_桌面与图形/Freedesktop.org/XDG%20桌面门户.md) 配合 PipeWire 实现，能够通过细粒度的访问控制在 Wayland 下共享内容

> **提示：**使用以下命令测试 WebRTC 屏幕共享是否正常工作[Mozilla 的 GetUserMedia WebRTC 测试页面](https://mozilla.github.io/webrtc-landing/gum_test.html).

> **注意：**[xdg-desktop-portal](https://archlinux.org/packages/?name=xdg-desktop-portal)包 1.10.0 修复了 D-Bus 接口的规范和实现之间的不匹配问题。 因此，某些客户端可能无法使用 xdg-desktop-portal 1.10.0 或更高版本。

Firefox (84+) 默认支持此方法，而在 Chromium (73+) 上，需要通过设置启用 [WebRTC PipeWire 支持](https://bugs.chromium.org/p/chromium/issues/detail?id=682122) URL `chrome://flags/#enable-webrtc-pipewire-capturer` 处的相应（实验）标志，或者使用CLI参数 `--enable-features=WebRTCPipeWireCapturer`。

[obs-studio](https://archlinux.org/packages/?name=obs-studio)包 (27+) 通过使用新的 PipeWire 捕获源支持此方法。

## 音频后期处理

### Pipewire 模块过滤链（module-filter-chain）

Pipewire 有一个名为[过滤链（filter-chain）](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Filter-Chain)的内部模块，可以创建节点来处理音频输入和输出。有关均衡、虚拟环绕声、LADSPA 插件和通道混合的示例，请参阅 `/usr/share/pipewire/filter-chain/`。

#### LADSPA

你可以从官方软件仓库安装各种 LADSPA 插件，并在 PipeWire 滤波器链中使用它们。

要列出特定文件提供的插件标签及可用控制参数，可以使用 [ladspa](https://archlinux.org/packages/?name=ladspa)包 软件包中的 `analyseplugin`：

```
$ analyseplugin /usr/lib/ladspa/lsp-plugins-ladspa.so
```

#### 全系统参数均衡

PipeWire 的滤波器链支持参数均衡器（Parametric EQ）。在 `/etc/pipewire/pipewire.conf.d/`（或 `~/.config/pipewire/pipewire.conf.d/`）目录中创建配置文件，然后参考以下示例，根据需要设置参数：

```
context.modules = [
    {
        name = libpipewire-module-filter-chain
        args = {
            node.description = "Equalizer Sink"
            media.name       = "Equalizer Sink"
            filter.graph = {
                nodes = [
                    {
                        type  = builtin
                        name  = eq
                        label = param_eq
                        config = {
                            filters = [
                                { type = bq_peaking, freq = 100, gain = 0.0, q = 1.0 },
                                { type = bq_peaking, freq = 500, gain = 0.0, q = 1.0 },
                                { type = bq_peaking, freq = 2000, gain = 0.0, q = 1.0 },
                            ]
                        }
                    }
                ]
                links = []
            }
            audio.channels = 2
            audio.position = [ FL FR ]
            capture.props = {
                node.name   = "effect_input.eq"
                media.class = Audio/Sink
            }
            playback.props = {
                node.name   = "effect_output.eq"
                node.passive = true
            }
        }
    }
]
```

你可以使用任意数量的滤波器。

如果需要前置放大器（Pre-amp），可以在频率为 0 的位置应用 `bq_highshelf` 滤波器，例如：

```
{ type = bq_highshelf, freq = 0, gain = -5.0, q = 1.0 },
```

重启 PipeWire，然后将「Equalizer Sink」设置为默认音频输出设备。此后，均衡器效果应会应用于所有应用程序。

或者，你也可以不指定 `filters` 数组，而是提供 `filename` 属性，指向由 [AutoEq](https://github.com/jaakkopasanen/AutoEq) 项目或 [Squiglink](https://squig.link/) 生成的参数均衡器配置文件，例如：

```
config = {
    filename = "/path/to/parametric.txt"
}
```

### EasyEffects

EasyEffects（以前的 PulseEffects）是一个 Qt 实用程序，它为各个应用程序输出流和麦克风输入流提供大量音频效果和滤波器。值得注意的效果包括输入/​​输出均衡器、输出响度均衡和低音增强、输入嘶声消除器和降噪插件。有关效果的完整列表，请参阅 [GitHub 页面](https://github.com/wwmm/easyeffects)。

> **注意：**Firefox 的麦克风音频流存在问题，参见 [EasyEffects 问题 #957](https://github.com/wwmm/easyeffects/issues/957#issuecomment-830640221)。

为了使用 EasyEffects，请安装 [easyeffects](https://archlinux.org/packages/?name=easyeffects)包。有关预设配置的集合，请参阅[社区预设](https://github.com/wwmm/easyeffects/wiki/Community-presets)。对于算法生成的耳机 EQ 预设的集合，请参阅 [AutoEq](https://github.com/jaakkopasanen/AutoEq)。

### NoiseTorch

NoiseTorch 是一种噪声抑制的替代方法，与 [noisetorch](https://aur.archlinux.org/packages/noisetorch/)AUR 打包在一起。另外还有-git版本[noisetorch-git](https://aur.archlinux.org/packages/noisetorch-git/)AUR。

启动后，可以为所选麦克风加载模块。可以调整语音激活阈值，应将其设置为最高级别，而不是过滤掉任何实际语音。

您可以使用 systemd 自动启动音频处理，请参阅 。请注意，如果从 AUR 安装，noisetorch 二进制路径会有所不同。

### 语音噪声抑制

安装 [noise-suppression-for-voice](https://archlinux.org/packages/?name=noise-suppression-for-voice)包 软件包，以使用适配 LADSPA 滤波器链的 librnoise，并安装 [swh-plugins](https://archlinux.org/packages/?name=swh-plugins)包 软件包以提供噪声门（Noise Gate）功能。

[GitHub](https://github.com/werman/noise-suppression-for-voice#pipewire) 上提供的说明基本仍然适用，但部分内容已经过时。在 PipeWire 1.6.3 中，滤波器链模块改为在预定义位置搜索插件，并[更改了插件格式](https://github.com/PipeWire/pipewire/commit/6bc07dfe0e18043aaf99f866b2c37f20e4a5e065#diff-ab0f086f94d735213c98cade15abd1caad434f9b7d555438791127d6b0be2f1b)。

> **注意：**如果按照上述说明进行配置，那么从 PipeWire [1.4.10](https://gitlab.freedesktop.org/pipewire/pipewire/-/releases/1.4.10) 开始，你可能需要明确指定音频输入为单声道（Mono）。可以通过在配置文件的 `capture.props` 和 `playback.props` 部分末尾分别添加以下两行来实现：

### JamesDSP

[JamesDSP for Linux](https://github.com/Audio4Linux/JDSP4Linux#readme) ([jamesdsp](https://aur.archlinux.org/packages/jamesdsp/)AUR) 为 PipeWire 和 PulseAudio 提供开源的音效实现。JamesDSP 使用自己的效果引擎，不依赖 LADSPA 或是 Calf 之类的东西。起初它被用于安卓设备的音效处理。

### LADSPA, LV2 和 VST 插件

如果你希望从所有可用的 LADSPA、LV2 和 VST 插件中自由选择，可以通过 [carla](https://archlinux.org/packages/?name=carla)包 配合 [pipewire-jack](https://archlinux.org/packages/?name=pipewire-jack)包 来使用这些插件。

启动 Carla，进入 *Settings > Configure Carla > Engine*（设置 > 配置 Carla > 引擎）。确保将 *Audio driver*（音频驱动）设置为 *JACK*，并根据需要选择合适的[处理模式](https://kx.studio/ns/dev-docs/CarlaBackend/group__CarlaBackendAPI.html#gaec3a1d85b80c5211a443b7afb3306ea6)。你也可以通过特定命令启动 Carla 来选择处理模式，例如使用 `carla-rack` 启动 *Continuous Rack*（连续机架）模式。

你可以手动将应用程序的音频输出连接到 Carla，但如果希望让多个应用程序的音频都经过 Carla 处理，在应用程序和 Carla 之间创建一个虚拟音频设备可能更加方便，并且可以选择将其设置为默认设备。首先，创建一个名为 `default_null_sink` 的空输出设备（null sink）。

```
/etc/pipewire/pipewire.conf.d/10-default-null-sink.conf (或 ~/.config/pipewire/pipewire.conf.d/10-default-null-sink.conf)
```

```
context.objects = [
  {
    factory = adapter
    args = {
      factory.name = support.null-audio-sink
      node.name = "default_null_sink"
      media.class = Audio/Sink
      audio.position = [ FL FR ]
      monitor.channel-volumes = true
      monitor.passthrough = true
    }
  }
]
```

重启 PipeWire 以使更改生效。

或者，你也可以使用 [pw-cli(1)](https://man.archlinux.org/man/pw-cli.1) 临时创建虚拟设备。如果安装了 [pipewire-pulse](https://archlinux.org/packages/?name=pipewire-pulse)包，也可以使用 [pactl(1)](https://man.archlinux.org/man/pactl.1)。详情参见 [PipeWire Wiki](https://gitlab.freedesktop.org/pipewire/pipewire/-/wikis/Virtual-Devices)。

在 *Rack*（机架）选项卡中，添加你需要的任意插件。确保这些插件为 *stereo*（立体声）类型。你可以调整插件的排列顺序。在 *Continuous Rack*（连续机架）处理模式下，列表顶部的插件会最先接收音频流，与 EasyEffects 中的处理顺序相同。随后，进入 *Patchbay*（接线板）选项卡，将 `default_null_sink` 的左右声道（L/R）监听端口连接到 Carla 的输入端口，再将 Carla 的输出端口连接到目标设备（扬声器、耳机、HDMI 等）的播放端口。将配置保存到本地文件，例如 `~/Documents/carla_sink_effects.carxp`。之后打开该文件时，Carla 会自动恢复这些连接。

你可以在多媒体应用程序播放音频时测试效果，例如使用 Firefox 观看网页视频。有两种方法可以实现。第一种是在 Carla 的 *Patchbay*（接线板）选项卡中，断开 Firefox 的所有连接，并将其左右声道输出连接到 `default_null_sink` 的播放端口。第二种是通过 [pavucontrol](https://archlinux.org/packages/?name=pavucontrol)包 找到 Firefox 的音频流，并将其重定向到 `default_null_sink`（系统应会记住该连接，以便下次启动该应用程序时自动将其重定向到相同的输出设备）。

要在启动时以 *Continuous Rack*（连续机架）处理模式运行 Carla 并加载保存的配置文件，可以创建一个 [systemd 用户服务](../../02_系统管理与内核/系统管理/Systemd_用户.md)：

```
~/.config/systemd/user/jack-carla-rack.service
```

```
[Unit]
Description=Load Carla Rack JACK host

[Service]
Environment=PIPEWIRE_LINK_PASSIVE=true
Type=exec
ExecStart=/usr/bin/carla-rack --no-gui %h/Documents/carla_sink_effects.carxp

[Install]
WantedBy=default.target
```

然后启用 `jack-carla-rack.service` [用户单元](../../02_系统管理与内核/系统管理/Systemd_用户.md)。

注意，如果你将 `default_null_sink` 设置为了系统默认设备，所有的应用声音都会被重定向至它，并且音量键也会改变它的音量而不是回放设备的。如果想控制回放设备的音量，需要把回放设备设成默认设备，然后将所需应用在 pavucontrol 里重定向到 `default_null_sink`（PipeWire兼容层应该会记住应用的连接关系）。
