# 第 31 章　媒体服务器

> 本章只解决一件事：把硬盘上的影视文件变成一个常驻后台、能随时被客户端点播的媒体库。全章只有《Emby》一节，必读，没有可跳过的部分——安装决定服务能不能起来，用法决定它对外呈现成什么样，写入权限决定它在无人看管时能不能稳定跑下去，三者是一条线，跳过哪一段都会在下一步卡住。
> 
> 最容易踩的坑，是把写入权限当成装完之后的收尾动作。Emby 长期以某个用户身份在后台读写媒体目录，装上包只是开始；权限没理顺时，服务看着启动了，问题却要等到某次写入时才暴露。读这一节时，把写入权限当作前提而非收尾。

## 31.1　Emby

*难度：入门 ｜ 篇幅：1.9 KB ｜ 所属：媒体服务器*

将要讲到：安装、用法、写入权限

[Emby](https://emby.media/) 是一个个人媒体服务器，它具有许多平台的客户端。它用于组织个人家庭媒体，以及在其他设备上播放。社区支持大量的频道，甚至可以与PVR和Tuner卡一起使用以远程提供电视流。

## 安装

安装 [emby-server](https://archlinux.org/packages/?name=emby-server)包 软件包。

## 用法

启用并启动 `emby-server.service`。

导航到 [http://localhost:8096/](http://localhost:8096/) ，通过浏览器访问 Emby。

## 写入权限

Emby 使用 systemd 的 DynamicUser 功能在[用户](../../08_安全与加密/安全/用户和用户组.md)和[用户组](../../08_安全与加密/安全/用户和用户组.md) `emby` 下运行。默认情况下，由于 systemd 的文件系统抽象，Emby 最多具有对媒体文件的读取权限。

（可选）您可能要授予 emby 写入权限并启用媒体删除或本地元数据保存。 为此，您可以扩展 systemd 服务：

```
/etc/systemd/system/emby-server.service.d/write-permissions.conf
```

```
[Service]
SupplementaryGroups=share
ReadWritePaths=/mnt/share
```

这会将 `emby` 用户添加到 `share` 组，并通过 systemd 启用对 `/mnt/share` 目录的写权限。请注意，您仍然需要确保 `share` 组对实际目录具有写权限。
